# 路口形态生成器 架构设计文档

> 版本: 1.0
> 工程语言: C++14
> 依赖: Eigen 3.4 (线性代数), nlohmann/json (JSON解析), ClipperLib (多边形布尔运算)
> 构建系统: CMake ≥ 3.15

---

## 1. 系统目标

为自动驾驶高精地图提供**自动化路口几何形态生成能力**，从结构化路网数据自动派生：

1. 路口内连通曲线（中心线）
2. 路口内车道边线（共享/独立）
3. 精细路口面（可内凹封闭多边形）

同时满足以下硬性需求：

- 端点G1连续 + 曲线无自相交
- 同簇线组非端点不相交（拓扑优先 + 横向倒置检测）；仅“左/右转 ↔ U型调头”允许穿越相交豁免，所有同簇曲线仍禁止非端点贴合/重叠
- 障碍物优先避障，避障与同簇非交约束综合处理
- 不贴合、重叠或穿行任何 Boundary/RoadEdge；`mode=2` 额外要求 RoadEdge 非端点 1m 净距（连接点自身就落在净距内时,端点邻域按"沿端点切向直行"的可达下限判定,见 6.8.10）；唯一豁免是"路缘折线端点就是该曲线连接点"造成的离开楔形与自指边界（见 6.8.7）
- 曲线不超出粗糙路口面；唯一豁免是连接点附近的坐标舍入（两级容差）与"粗糙面本身不含两连接点之间直线弦"造成的几何强制外溢（见 6.8.8）
- 输入固有形态保留（非U型仅穿障时可重生成；U型调头固定形态也按强形态规则重生成）
- 调头形态使用"首端直行段+单段掉头弧+尾端直行段"三段式表达，无Crosswalk时首尾直行段需向路口内拉伸至少2m再掉头，有Crosswalk时首尾直行段必须完全跨越过Crosswalk面后再掉头
- 无障碍、无Boundary/RoadEdge避让、无同簇非豁免交叉避让、无固有形态影响时，普通直行/左转/右转必须用单段Bezier表达：直行平直，左/右转为单拱弧；一旦单段候选会违反同簇非交或物理约束，该曲线进入避让路径，仍禁止S形。
- 普通单段Bezier的两个内部控制点只能沿首/尾连接点原始方向轴移动，默认不得超过端点弦长；非直行、非U型调头的两条方向射线存在前向交点时，控制点必须位于端点与该交点之间。掉头和经物理避让判定无轴向单段解的曲线走专用例外路径，并由最终审计标注无解/降级。
- 同入口/同出口同向线束除首尾连接点外不允许共享 lead、贴合或重叠；U型调头对必须按同入/同出传递连通分量在首尾直行拉齐到同一站位后由大径包围小径，任何曲线不得单独继续轴向前推；同分量多条U型调头要按左到右顺序的逆序N做N×0.01m级平齐点相向错开，短径平移更多、长径平移更少，同出口中弧退出侧控制点必须保持簇排序，不能把相邻中弧交叉裁成合法重叠。

## 4. 核心模块职责

### 4.1 IntersectionShapeGenerator (顶层调度)

负责：
- 输入数据规范化（补全enterGroupId/exitGroupId）
- 输入/输出几何坐标保留 `Vec3d` 高程；平面约束按 XY 投影运行，生成曲线采样按入口/出口端点高程沿弧长插值
- 拓扑校验
- SDF场构建
- 调度三个子生成器
- 异常捕获与回滚
- 性能统计

接口：
```cpp
class IntersectionShapeGenerator {
    bool generate(const IntersectionInput&, IntersectionOutput&);
    const ValidationReport& lastReport() const;
};
```

### 4.2 ConnectivityGenerator (核心生成器)

负责：
- 全局生成顺序规划 (GlobalCoordinator)
- 同簇排序求解 (ClusterOrderSolver)
- 单条曲线生成 (generateOne)
  - 兄弟曲线构造
  - 初始曲线构造（普通/U型调头分支）
  - LBFGS优化
  - 后处理（G1强制/细分/平滑）
- 多轮拓扑修复
- 违规标注

### 4.3 ClusterOrderSolver (拓扑排序)

负责：
- 进入簇/退出簇空间排序
- 同簇配对构造
- 结构性交叉检测
- 共享端点标记
- 障碍物豁免A2标记
- O(1)哈希索引查找

数据流：
```
Connectivity[] + Lane[] + LaneGroup[]
       │
       ▼
   build()
       │
       ├──► entry_group_order_[gid] = [conn_id_sorted]
       ├──► exit_group_order_[gid]  = [conn_id_sorted]
       ├──► pairs_ = [CurvePair{...}]
       ├──► entry_cluster_rank_, exit_cluster_rank_
       └──► pair_index_ = {conn_id → [pair_idx]}
```

### 4.4 SDFField (符号距离场)

负责：
- 多边形障碍物栅格化
- 带梯度的SDF查询
- 静态缓存复用
- 局部区域更新

性能优化：
- 稠密网格 + 双线性插值
- CacheKey 哈希（roi + obstacles + cs + buf）
- 内部使用 ClipperLib 做多边形并集与缓冲

### 4.5 PenaltyCost (代价函数)

联合代价：
```
F(params) = w_smooth × ∫κ²ds
          + w_obstacle × Σ max(0, cl - sdf)²
          + w_boundary × (Σ boundary_intersections + Σ road_edge_outside²)
          + w_fence × Σ outside_fence_dist
          + w_cluster × cluster_violation
          + w_crosswalk × crosswalk_oblique_traversal
```

权重自适应：
```
每轮外层迭代后:
  若该项违规量 > 1e-3: 权重 ×= 1.5~2.0
  上限: obstacle≤240, boundary≤160, fence≤96, cluster≤96
```

### 4.6 LBFGSSolver (优化求解器)

实现细节：
- 双循环递归计算逆Hessian近似
- Strong Wolfe线搜索（c1=1e-4, c2=0.9）
- 历史记录m=10
- 最大80次迭代
- 梯度收敛阈值5e-4

支持冷启动 (`solve`) 和热启动 (`solveWarm`)。

## 6. 关键设计决策

### 6.1 拓扑优先于几何

簇排序与结构性交叉检测在曲线生成**之前**完成，确保：
- 生成顺序正确（内→外）
- 不可避免交叉被提前豁免（StructuralCross）
- 兄弟曲线携带正确的`expected_side`进入优化器

### 6.2 U型调头显式分段与Bezier表达

U型调头内部仍可用单段三次Bezier候选辅助搜索，但最终形态必须输出显式"首直+中弧+尾直"三段式：
- 优化变量更少（4控制点=8参数）
- G1连续由构造保证（非约束）
- 拱弧顶点位置可控（lead0/lead1+lateral_bias）

生成器优先输出显式三段式，确保调头先沿进入方向直行、再用单段中间弧形转向、最后沿退出方向直行。弧段两端点沿U型轴线平齐；有Crosswalk面时首尾直行段跨过人行横道，无Crosswalk面时首尾至少向路口内拉伸2m。该表达用于保护 `intersection_ds.json` 的 `20|22`、`intersection_jd.json` 的 `4|34`，也覆盖 `100000012-nu.json` 中 fixed U型调头。

### 6.3 网格搜索 + 局部优化组合

U型调头先做场景化网格搜索确定拓扑正确性：
- 纯几何冲突场景扩展横向/深度搜索；
- 有 Boundary 的无障碍场景限制大横移候选，优先用 lead 深度和最终 pair repair 分离同簇；
- 初始求解已使用完整兄弟集合时，不重复执行同一网格。
必要时再交由LBFGS做局部精细化，避免局部最优陷阱。

### 6.4 SDF静态缓存

相同输入的SDF场复用，避免重复栅格化。
CacheKey 包含 roi/obstacles/cs/buf 全部影响因子。

### 6.5 共享端点连接点容差

同簇曲线共享退出/进入车道时，端点附近必然汇聚，
仅首尾连接点本身允许相遇。实现上只用小范围数值容差排除端点采样误差，
连接点外的贴合、重叠或相交仍作为违规；唯一业务相交豁免为
`左/右转 ↔ U型调头` 的几何穿越，贴合/重叠不在豁免范围内。

### 6.6 人行横道跨越仅基于Crosswalk面

`crosswalkClearanceAhead` **仅**使用输入数据的Crosswalk多边形：
- 不使用stop_line作为代理（与Crosswalk概念不同）
- 多个Crosswalk落入同一射线搜索带时，先按近端投影选择从组端点朝路口中心遇到的最近Crosswalk，再使用该面远端 `far` 作为跨越距离
- 进入/退出两侧都命中Crosswalk时，U型调头中弧只按这两侧选中的面做跨越保护；仅单侧命中时保留全量Crosswalk支持，避免另一侧lead被压短
- 无Crosswalk数据时返回0，不施加任何跨越约束
- 避免引入任意偏移导致同arm上调头apex深度不对称

### 6.6.1 三段式掉头候选搜索的两阶段包装

`ConnectivityGenerationSession` 不直接调用 `SegmentedUTurnCandidateSearch::search`，而是经 `searchSegmentedUTurnTwoPass` 统一入口（6 处调用点：5 处生成路径 + 1 处 pair repair）：

- **第一阶段**用严格同簇判定，行为与引入本包装前逐字节一致。
- **第二阶段**只在"走廊翻转型死局"下启动，需同时满足：① 第一阶段一无所获；② 入参曲线确实违反人行横道分段要求；③ `segmentedUTurnCorridorInverts` 判定端点走廊在平齐站位处翻号。此时审计器改用放宽版 `curvesHaveForbiddenSameClusterIntersection(..., allow_merge_funnel = true)`，把共享端点的汇入收敛段挖成豁免球（`curvesIntersectBusinessOutsideBalls`），收敛段之外仍是硬违约。
- **热路径零成本**：`allow_merge_funnel` 默认为 `false`，收敛段半径只在"严格判定已报违约且放宽已开启"时才计算。早期版本无条件计算，单路口耗时由 16.7s 翻到 33.1s。
- 落实层配套的是 `UTurnCurveInitializer::buildSegmented` 的 `enforceStationCorridorFloor`（平齐站位走廊底限，仅在有符号走廊 ≤ 0 时介入）。二者一个负责"让三段式解存在"，一个负责"接受几何上不可消除的残余"，缺任一个 `110000703-u` 的 `41` 都会退化为单段。

### 6.7 多轮修复

最多3轮全局修复，每轮最多修复12条曲线：
- 第1轮：纯几何拓扑修复 (tryPureGeometryTopologyRepair)
- 第2轮：U型调头专用修复 (generateOne with allow_uturn_search=true)
- 第3轮：标记Degraded

### 6.8 八重约束的协同机制

路口曲线生成同时满足8重约束，它们相互制约：

| 约束 | 权重/优先级 | 冲突对象 | 解决方案 |
|------|-----------|---------|---------|

#### 6.8.1 避障 vs 同簇非交协同
- 权重优先级: 避障(30) > 簇(20) > 围栏(6)
- 避障违反时自适应放大至240,簇至多96
- `checkAndMarkA2`: 若避障导致必须交叉,标记ObstacleCross弱化簇约束至0.4×(非零,保持基本保序)

#### 6.8.2 同簇非交 vs 人行横道跨越协同
- 同arm多U型调头获得不同跨越距离 → 拱弧顶点深度不一致 → 破坏有序排列
- 解决: `crosswalkClearanceAhead` 先选近端投影最近的Crosswalk，再用其 `far`(远端投影)而非 `forward`(最近点投影)作为跨越距离
- U型调头求解器同时搜索 `lead0_extra` 与 `lateral_bias`,保持两条拱弧横向有序

#### 6.8.3 G1 vs 同簇非交协同
- G1由构造保证(makeCubicG1/makeAlignedUTurnCubic)
- 优化后 enforceG1 强制投影回切向射线
- 簇约束通过控制点偏移而非切向调整,与G1正交

#### 6.8.4 固定形态 vs 避障协同
- `fixedGeometryHitsObstacle` 检测固有形态是否穿障
- 非U型固定形态仅穿障时允许重新生成,其他场景保留
- U型调头固定形态不进入 `preserved_fixed_ids`,统一重生成三段式以满足强形态约束
- 重新生成时仍满足其他所有约束
- 「挡住邻居自然形态」这一撤保护理由要求该邻居的自然单段候选**物理可达**：
  `naturalSingleSegmentCandidate` 在形态过滤之后再判一次障碍/Boundary/精围栏
  （`assessCurveRisk(...).physical()`，同簇交叉不参与以免自我循环）。若邻居的自然
  候选本身就物理不可用,它无论如何都会走避让路径、永远不会采用该形态,此时牺牲
  固有形态是纯粹的损失
- 自指边界数据：`100000385-u`（929910/929913/929914/929916）与 `100000012*`
  （43285424/25/26）把同一条折线**同时**声明为 RoadEdge 与右转连接的固有形态,ID
  相同、坐标逐位一致。这些连接"穿越"的正是自己,必须豁免（见 6.8.7）,否则它们
  永远 `status=Degraded`,并且会以"边缘"身份把同簇邻居挤出自然形态

#### 6.8.5 U型调头多约束联合求解
`solveUTurnMultiConstraint` 网格搜索 `scale × lateral_bias × lead0_extra × lead1_extra × handle_bias`。障碍场景使用紧凑网格控制耗时；纯几何场景使用更宽网格，并在评分中启用近重叠检测，解决同入口/同出口 U 型调头的首段重叠和包络排序。

```
cost = 1000 × sib_x            // 同簇交叉数(高权重)
     + 200  × obst_pen         // 障碍物穿透
     + 200  × fence_ovf        // 围栏越界
     + 50   × (1 - g1_min)     // G1偏离
     + 20   × max(maxk-1, 0)   // 最大曲率
     + 5    × |arc/c - 1.55|   // 拱弧形态偏离
     + 0.5  × (|lat_bias|+|handle_bias|+0.3·lead0_extra)  // 紧凑度
     + 0.1  × |arc - ref_len|  // 弧长偏离
```

硬过滤: 自相交/超出envelope/曲率超物理上限 → 拒绝

纯几何大 U 型调头需要显式分段时，直接构造“首直+单弧+尾直”候选，不再用拆分单段曲线伪装分段。完整曲线集合生成后，残余 U 型调头冲突使用 U 型调头专用重生成；最终通用单段拓扑修复只处理非 U 型曲线。

#### 6.8.6 生成顺序保证
按"直行→左右转→U型调头"+"由内到外"顺序生成,确保外侧曲线生成时内侧邻居已就绪,作为兄弟传入携带正确的 `expected_side`。

#### 6.8.7 共享连接点的离开楔形豁免
RoadEdge 折线的端点常常**就是**某条连接的连接点（路缘自车道端点起画）。两条从同一
点出发、夹角不到 1° 的线必然在几米内交叉一次,随后各走各路：这不是"曲线穿越路缘",
而是折线端点重合造成的拓扑必然。`100000385-u` 的直行 59 与路缘 929910 实测最大偏离
`0.037m`、在 `3.58m` 处交叉,却因此否决了全部 11 个自然直行候选,把 59 压成约 `6m`
的 S 形鼓包。

`curveBoundaryContactsAreDepartureWedges`（`constraints/boundary_safety.h`）只在严格
判定已报违、且未涉及 `outside_road_edge` 时被调用,要求**所有**判违接触逐条落入豁免：
- 折线端点距曲线连接点 ≤ `anchor_tol = 0.20m`（`O(B)` 快路径,一条都锚不上直接否决）
- 从该连接点到最远接触的跨度 ≤ `wedge_span = 6.0m`
- 该区间内曲线到折线的最大偏离 ≤ `wedge_tol = 0.05m`（与 `outside_tol` 同值）
- 或：首尾连接点都锚在折线端点上且全程偏离 ≤ `wedge_tol`（自指边界,见 6.8.4）

corpus 实测两类样本相隔一个量级：真实楔形深度 `0.0001~0.087m` / 跨度 `0.6~4.0m`；
真实贴合或切入深度 `0.10~4.22m` / 跨度 `8~36m`。该豁免**不是**已废止的
`endpointGraze`：不做切向对齐、容差紧 5 倍（`0.05` vs `0.25m`）、窗口以最远接触为界,
因此"越出 5cm 后又折回相交"仍然判违。生成器与最终审计共用
`curveBoundarySafetyForInput`,口径自动一致；`curveBoundaryStrictSafetyForInput` 保留
严格入口作对照。回归见 `tests/test_intersection_input_regression.cpp` 的 `[wedge]`。

#### 6.8.8 粗糙路口面越界的可归因化：连接点舍入与弦强制下限
粗糙路口面的外环是从各进出口车道端头连出来的,因此**外环恰好穿过每条曲线的连接点**。
由此产生两类不可归因于生成器的"越界",必须在判违前剥掉,否则围栏类误报会淹没真实缺陷
（corpus 实测 76 条 error 里 70 条属于此列）。

**一、判据同口径。** 历史上布尔与数值两条通路采样点集不同——`curveInsideFence` 对每段
按参数取 `seg.evaluate(i/sps)`,`curveFenceOverflow` 对整条按弧长取点——在连接点附近落点
不同,对同一条曲线可给出**相反**结论（`fence.containment` 报违而 `generator.fence_overflow`
为 0,或反之）。现在两者与优化罚项 `PenaltyCost::evalFence` 共用同一逐采样点谓词
`fenceOutsideIsConnectionPointRounding`,矛盾消除。审计密度 `profile.samples = 64`,
库内默认 25。

**二、两级豁免。** 连接点本身与其近侧的自由度不同,容差也不同：

| 层级 | 判据（`ep` = 到最近连接点距离） | 允许外溢 | 依据 |
|---|---|---|---|
| 一 | `ep ≤ kFenceConnectionPointRadius = 1e-3m` | `kFenceEndpointOutsideTol = 0.05m` | 连接点由输入车道端点决定,生成器自由度为零,"在环内还是环外"纯由坐标舍入决定；容差只用来防"车道端点被数据放到面外很远"的真实数据错误 |
| 二 | `ep ≤ kFenceConnectionSpan = 0.20m` | `kFenceConnectionRoundingTol = 0.0025m` | 离开切向同样被输入车道方向固定；若它几乎与穿过该点的外环边平行,离开后数厘米内会成片读出亚毫米外溢,**且采样越密读出越多** |

采样密度依赖是实测的：`intersection_cross` conn 61 在 `sps=25` 只命中
`seg=2 t=1.0000 dist=0.000612m ep_d=0`,`sps=64` 额外命中
`seg=2 t=0.9844 dist=0.000234m ep_d=0.041540m`。跨度 `0.20m` 与 6.8.7 的 `anchor_tol` 同值。

corpus 定标（`sps=64`,967 个界外采样点）：界外点全在 `0.20m` 内的 18 条曲线最大外溢
`0.001665m`；存在 `0.20m` 以外界外点的 26 条最大外溢 `0.0038~8.7518m`。分界取几何中点
`0.0025m`,两侧各留约 1.5 倍余量。**豁免是逐采样点的**,真实外溢即便从连接点附近起步
（实测最小起步 `0.000244m`）,其增长段的 `ep_d` 必然远超 `0.20m`——26 条真实外溢曲线的
最大外溢点 `ep_d` 全部 ≥ `2.0m`,仍会被报出。

**三、弦强制下限。** 粗糙面常把各进出口喉部用**直线弦**连起来,于是整块转角被切掉。两个
连接点固定不可移,若连它们的直线弦本身都在面外,则任何曲线都出不来,外溢的下限就是弦
外溢——成因是面画小了,不是曲线画歪了,右转尤甚。`fenceChordOverflow` 给出该下限,
`fenceOverflowForcedByFace(curve, chord)` 判 `curve ≤ chord + kFenceConnectionRoundingTol`
（低于舍入尺度的差值无物理意义,且两者采样点集不同本身就带这个量级的误差）。命中则
`fence.containment` 记 `ConstraintState::Exempt`（审计渲染为 `info`）并带上弦外溢作证据,
否则记 `Violated` 且 `violation = 曲线外溢 − 弦外溢`,即"比直连还差多少"。

corpus 实测：8 条右转曲线外溢 `0.14~1.96m` 而弦外溢 `2.91~4.39m`（曲线已比直连好得多,
是优化器向内挤压的结果）；右转与直行 10 例全部满足 `曲线 ≤ 弦`；真正超出的 3 例分别超出
`0.0018m`（低于舍入尺度,判强制）、`0.2386m`、`5.2154m`（判形态缺陷）。据此围栏类 error
由 76 条降到 6 条,余下 `100000643`/`-0` conn 94（直行,超 `0.2382m`）与 `110002137`
conn 21（掉头,超 `5.2406m`；弧长 `83.354m` 对弦 `24.974m`,同时违反 RoadEdge 净距,
围栏外溢是畸形掉头的症状而非病因）。

**已知漏报**：若面确实切掉转角,而曲线外溢略小于弦外溢但形态不合理（例如贴弦而非向内挤）,
本判据会判强制。选择接受——在"面不含弦"的前提下"合理形态"没有可判定的下界；形态本身仍
由 `shape.*` 与 `physical.*` 各类独立把关。回归见 `tests/test_refactored_modules.cpp` 与
`tests/test_intersection_input_regression.cpp` 的 `[fence]`,诊断工具见 `tests/diag_fence.cpp`。

#### 6.8.9 同组切向统一的跨臂误并保护
`ConnectivityDirectionNormalizer`（`ConnectivityDirectionMode::GroupUnified`）的用途是抹掉
**同一进出口内平行车道之间**的切向抖动：给整组选一个方向（优先取进出夹角最小的 `Straight`
连通,同角度再比横向偏移；无直行时用矢量和/最左车道兜底）,再把组内每条车道的端点切向
改写成该方向（在端点内侧 1.0m 处插入合成点实现）。`CON_NUM == 1` 的车道跳过。

**问题**：实现原本不检查"被强加的方向与车道自身朝向差多少"。一旦输入把**两条物理方向
不同的路口臂**塞进同一个 `groupId`（`110004764` 的 `43107602`：五条车道朝 `-11.5°`、两条朝
`-83°~-88°`）,少数派车道的端点切向会被整整扭转几十度。之后以它为端点的每一条曲线都在
**错误的切向**上做 G1,于是必然自交、越过路缘、与同簇兄弟成片相交——而审计用的是同一份
规范化输入,`g1.endpoint` 反而读不出异常,违规表现为下游的形态与相交缺陷,根因不可见。

**判据**：组方向与车道自身朝向的夹角超过 `kGroupDirectionForceLimitDeg = 20°` 时**不覆盖**
该车道端点切向,保留其原朝向。20° 取自 corpus 定标（`tests/diag_group_dir.cpp`,
`--limit 1e9` 可关闭保护重新扫）：合法抖动集中在 `0~6°`,跨臂误并集中在 `22~88°`,中间是空的。

**抗抖动**：车道自身朝向不能只看端点两点式切向（`entryLineTangent`/`exitLineTangent` 只用
最后/最前两点）。末段短到几十厘米时方向被数字化噪声主导——`110000703-u` 的 `43106568`
整条 `52.67m`、末段仅 `0.31m`,两点式虚报 `23.8°` 偏差,而自端点回溯 `3m`
（`kGroupDirectionRobustBaselineM`）的弦只差 `1.87°`。故取**两者的较小值**作判据：两个估计
的失效模式互补（短末段被噪声主导；转向口袋里整条弦会偏离端点朝向）,只有两者都认为偏差
过大才算跨臂。二者均可经 `ConnectivityDirectionConfig::group_force_limit_deg` /
`group_robust_baseline_m` 覆盖。长基线弦**不是**幂等的,依赖 normalizer 每次 `run()` 只在
输入副本上执行一次。

**实测**：保护命中 6 条车道（`43107974`、`43106520`、`43104631`×2 数据集、`43102472`、
`43102461`）,corpus error 由 175 降到 158,其中 `110004764` 由 48 降到 24
（自交 2→0、同簇相交与 `generator.status` 成片消失）。回归见
`tests/test_integration.cpp`、`tests/test_refactored_modules.cpp` 与
`tests/test_intersection_input_regression.cpp` 的 `[group_direction]`。

#### 6.8.10 RoadEdge 净距亏欠的可归因化：连接点强制下限
`mode=2` 要求曲线非端点处距 RoadEdge ≥ 1.0m（`roadEdgeAvoidanceClearanceForMode`）。但
**连接点位置由输入车道端点固定,端点切向又被 G1 锁在车道朝向上**：若连接点自身就落在净距
之内（`110000741-u` 出口连接点距 RoadEdge 仅 `0.9521m`）,端点邻域的亏欠不是"曲线选错了
形状",任何合法曲线离开该点时都只能沿切向走,净距按 `d(s) ≈ d(0) + s·sinθ` 缓慢恢复。

不豁免的后果是级联的：`assessCurveRisk` 与严格族物理门禁都按 `> 0` 判物理风险,于是每个
单段候选都被判不可行,生成器放弃合法单段三次曲线、升级成两段绕行（实测 `maxk 2.10`）,
绕行再被 `shape.ordinary.waypoint` 判非法,两条绕行之间又相互相交——一个不可满足的硬约束
把三条本来只差几毫米的曲线全部推成了真正的违规。

**判据**（`src/constraints/road_edge_clearance.h`,生成与审计共用）：逐采样点比对"可达下限"

| 采样点位置 | 判定下限 | 依据 |
|---|---|---|
| 到较近连接点距离 `s ≤ kRoadEdgeClearanceEndpointSpan = 1.0m` | `min(clearance, d(端点 + s·端点切向))` | 零曲率方案总是可达的;低于它才是曲线自身形态造成 |
| `s > 1.0m` | `clearance`（全额） | 出了影响区只需横向让出几厘米,任何曲线都做得到 |

亏欠取逐点超出量的最大值（`roadEdgeClearanceDeficit`）,舍入容差
`kRoadEdgeClearanceRoundingTol = 0.0025m` 与围栏连接点舍入同量级。净距不足但逐点亏欠为零时
（`roadEdgeClearanceForcedByEndpoint`）,审计记 `ConstraintState::Exempt`（渲染为 `info`）,
生成侧不据此判物理风险；否则记 `Violated` 且 `violation = 最大亏欠`。软罚项
（`penalty_cost.cpp` 的 `road_edge_clearance`,权重 20）**不豁免**,继续把曲线往外推。

**两个刻意的取舍**：① 曲线额外弯离路缘最多再挣得 `κs²/2`（`κ≤0.25`、`s≤0.5m` 时约 3cm）,
这部分不追究——此处曲率预算已被转向半径本身占用,把理论弯曲余量算作"本该做到"会让唯一
合法的单段曲线被判违规。② 影响区上限 `1.0m` 不可省略：距离函数沿与路缘平行的射线几乎不
增长,若不限范围,任何与 RoadEdge 长距离平行且净距略欠的连通都会被整条豁免,硬约束等于作废。

**不要反用 1-Lipschitz 界**。`d(端点) + s ≥ clearance` 只说明全额净距不违反距离函数的增长
上限,**并不表示它可达**——那需要曲线垂直于路缘离开,而端点切向通常近乎平行于路缘。早先按
该式提前返回全额 clearance,判据比上表更严,`110000741-u` 的合法单段曲线被判 `0.0427m`
亏欠并触发绕行升级。

**实测**：`physical.road_edge_clearance` error 由 11 降到 3,corpus error 由 158 降到 150
（连带修好 `110002479` conn 21）,新增 error 0。回归见
`tests/test_intersection_input_regression.cpp` 的 `[road_edge_clearance]`。

#### 6.8.11 共享端点族的自然参照候选与闭包"先窄后宽"升级

共享端点扇出族（同一 `entry`/`exit` 的多条普通连接）的次序是一个**全序性质**：族内成员
共用 P0 与入口切向，端点附近只由转入速率 |κ0| 区分。单段三次曲线有
|κ0| = (2/3)·|lat(P2)|/h0²,把手 h0 越大 |κ0| 越小,因此"每个成员按自身端点几何推出的
把手"（`OrdinaryCurveInitializer::buildPreferredSingleCubic`）天然单调、互不相交。

**自然参照候选**。严格族与闭包的候选池原本只在把手分数网格上取样,网格步长在
`0.20→0.32→0.48` 之间跨度过大,恰好可能把"整族回到自然表达"这个必然合法的组合跳过。
现在两个池都把自然形态以 `score = -1.0` 排在首位（`strict_natural_reference_candidate`,
经控制点合法性、自交、形态门禁过滤）,于是 DFS 的**第一个探测叶子**就是整族的自然表达。
无额外搜索成本。

**闭包"先窄后宽"升级**。族内收口失败时会把跨端点阻塞者纳入有限闭包联合求解。关键结论:
**闭包变量越多不等于越强**。每个新变量都会引入新的同簇硬约束行,AC3 可能直接清空某个
成员的候选域,于是本来有解的小闭包退化成无解的大闭包,连原先已修好的对也一起丢失。
实测 `110003285` 的 `entry:43103892`（成员 9,10,14,24）在窄闭包下
`committed members=5 nodes=6`,一次性把预算开到最大后变成
`closure_nodes=0`,重新冒出 `9|10`、`24|14` 两条同簇相交。

因此扩张预算按族逐轮升级,而不是全局放大：

| 参数 | 首轮 | 升级重试轮 |
|---|---|---|
| `kMaxStrictClosureMembers` | 6 | 10 |
| `closure_discovery_per_round` | 1 | 2（族成员 ≥ 4） |
| `closure_max_rounds` | 1 | 3（族成员 ≥ 4） |

升级入口是 `closure_escalate`：只对**上一轮确实搜索失败且尚未升级过**的族生效
（`strict_failed_last_pass` / `strict_escalated_families`）。族收口的多轮循环原先在
"本轮无改写"时立即 break,现在只要还有待升级的失败族就继续下一轮,每族最多升级一次,
仍受 3 轮上限、每成员 32 候选截断与 50000 闭包节点预算约束。

上限放宽到 10 的必要性：共享入口扇出族本身就可能有 6 个成员（`110004764` 的
`43106530` 有 8,10,11,12,13,14）,此时若闭包上限仍是 6,扩张循环的
`closure_ids.size() < kMaxStrictClosureMembers` 直接为假,跨端点阻塞者（41、47）永远
进不了变量集,而族内搜索的叶子判定要求对外部关系也彻底干净,于是整族必然失败。

**实测**：corpus error 150 → 147（`110002473-u` 的 `5|6`、`5|7`、`5|8` 修好）,findings
404 → 396,新增 error 0；最慢用例 `110004764` 6.21 → 6.59 秒,仍远低于 15 秒上限。回归见
`tests/test_intersection_input_regression.cpp` 的 `[closure]`（两个方向各一例：
`110002473-u` 必须靠升级修好,`110003285` 必须保住窄闭包的解）。

**已知未解**：`110004764` 的 `43106530` 扇出仍是 24 error。根因不在搜索预算——成员 12、
13 的自然形态**真实穿越输入 Boundary**（1201 采样下仍 `intersects=1`）,族序与边界可行性
在该数据上不可同时满足；且阻塞边界全是 `type=3 (Other)` 而非路缘,其中
`43100474`/`43100479` 是同一条边被画了两遍（端点相同、相距约 0.5m,形成 10m×0.5m 薄片）,
属输入数据缺陷。另外 `curveBoundarySafety` 每段最多 80 采样
（`src/constraints/boundary_safety.h:435`）,对 77m 长曲线只有约 0.97m 间距,成员 11 的
边界拒绝是该采样上限造成的**误判**,记入待办。

## 7. 性能架构

当前性能目标为单路口通常毫秒级完成，**最差不得超过 15 秒（产品上限）**；2026-09-05 全量 25 份数据集在 Release（`-O3 -DNDEBUG`）下合计 43.3 秒（`diag_gen_time`，超上限 0/25），最慢 `datas/110004764.json` 6.81 秒、`datas/100000385-u.json` 6.31 秒、`datas/100000643.json` 3.85 秒，中位数在 1.1 秒量级。主要策略：
- LBFGS 默认迭代从 30 降到 12，线搜索从 8 降到 4，候选初解承担主要约束满足，优化器只做局部修正。
- 曲线交叉采样从 0.20m/240 点收敛到 0.35m/160 点，兄弟曲线默认采样从 48 降到 32。
- 非纯几何场景关闭昂贵全量 residual pass，只做 1 轮、最多 8 条曲线的小预算重生成。
- U 型调头候选按场景切换：障碍场景紧凑搜索，纯几何场景才扩大横向/深度网格。
- 判交与边界检查全面引入分层包围盒剪枝（成对曲线每 16 段一个粗盒、采样折线×边界折线逐段盒），以及按内容为键的记忆化（成对采样、边界安全段、`findLane`）；掉头家族联合搜索按成员建入射配对索引并对候选池做基线预过滤。全部以"被跳过的工作结论必然相同"为前提，等价性回归见 `tests/test_perf_caches.cpp`，逐项说明见 `docs/软件开发完整文档.md` §7.2。

### 7.1 空间索引

- **QuadTree**: 持久化四叉树，加速同簇兄弟曲线查询
- **PairIndex**: 哈希索引，O(1)查找CurvePair
- **SDF Grid**: 稠密网格 + 包围盒限界

### 7.2 缓存

- **SDF静态缓存**: 跨调用复用
- **PenaltyCostCache**: 每外层迭代重建，存储采样点列
- **SampledSiblingCurve**: 预采样避免重复采样

### 7.3 并行化潜力

当前为单线程，可并行化点：
- 不同priority group的曲线生成（弱依赖）
- LBFGS代价函数的项计算（smooth/obstacle/boundary/fence/cluster独立）
