## 1. 需求说明

### 1.1 项目背景

本工程为自动驾驶高精地图生产流水线中的路口几何形态自动生成模块。
给定路口的结构化路网数据（车道组、车道、连通关系、障碍物、边界等），
自动计算出路口内部的连通曲线、车道边线和精细路口面，
以供下游地图制作、导航规划、仿真验证等系统使用。

### 1.2 系统输入

| 数据类型 | 关键字段 | 说明 |
|---------|---------|------|
| `LaneGroup` | id, role(Entry/Exit), lanes, boundaries | 同方向同侧车道组 |
| `Lane` | id, left_edge_id, right_edge_id, width, geometry, laneOrder | 车道，进入车道末点/退出车道首点为路口端点 |
| `LaneEdge` | id, geometry, is_shared, shared_by | 车道边线 |
| `Connectivity` | id, entry_lane_id, exit_lane_id, turn_type, geometry(可选固有形态) | 连通关系，geometry 非空时表示固有形态 |
| `Obstacle` | id, geometry, buffered_geometry | 多边形障碍物 |
| `Boundary` | id, type(RoadEdge/MedianStrip/GreenBelt/Other), geometry | 道路边界线 |
| `StopLine` | id, geometry, associated_group_id | 停止线 |
| `Crosswalk` | id, geometry(Polygon2d), crossing_direction | 人行横道面 |
| `IntersectionArea` | id, geometry, is_rough | 粗糙路口面（约束围栏） |
| `mode` | int(1/2/3) | 路口模式：1=bxn，2=jd，3=ds，影响障碍物/RoadEdge 清距和缩扩方向 |

### 1.3 系统输出

| 数据类型 | 说明 |
|---------|------|
| `ConnectivityCurve` | 每条连通关系对应的 Bezier 中心线，包含状态和违规信息 |
| `ConnectivityLaneEdge` | 路口内车道边线（支持相邻车道共享） |
| `IntersectionArea` | 精细路口面（可内凹封闭多边形） |
| `PerfStats` | 各阶段耗时统计（毫秒） |

坐标系统：统一使用三维 `Vec3d{x, y, z}`，高程 `z` 由输入提供或按弧长插值；
所有约束计算在 XY 平面投影进行，Z 仅随输出坐标保留。

### 1.4 功能需求

#### 1.4.1 连通曲线生成（核心）

生成需同时满足以下 8 重约束：

| # | 约束名称 | 强度 | 说明 |
|---|---------|------|------|
| C1 | G1 端点连续 | 硬约束（由构造保证） | 普通直行/左转/右转曲线首末点切向与进退车道 G1 连续，曲线自身不自相交；U型调头首尾连接点按业务特殊场景跳过G1检查 |
| C2 | 同簇非端点不相交 | 硬约束（权重 20，可至 96） | 同进/出连接点的线簇除端点外不得相交；仅"左/右转↔U型调头"豁免 |
| C3 | 障碍物避让 | 最高优先级（权重 30，可至 240） | 禁止穿行障碍物；mode=2 时需额外保留 1m 绕障距离 |
| C4 | 不贴合/重叠/穿行道路边缘 | 高优先级（权重 10） | 禁止与 Boundary/RoadEdge 非端点贴合、重叠、相交或越到外侧；mode=2 非端点需保持 1m 净距 |
| C5 | 不超出粗糙路口面 | 中优先级（权重 6） | 曲线不得超出输入 IntersectionArea 的粗糙面围栏 |
| C6 | 人行横道跨越 | 硬约束（min_lead 参数） | 调头曲线的首/尾直行段必须完全跨越人行横道面 |
| C7 | 固有形态保持 | 条件保留 | 有固有形态时原则上不修改；仅穿障时允许重新生成；U 型调头固有形态必须重新生成三段式 |
| C8 | U 型调头三段式 | 硬约束（形态约束） | 调头必须为"首端直行段+单段掉头弧+尾端直行段"；无 Crosswalk 时首尾至少向内延伸 2m；按同入/同出传递连通分量严格获得唯一轴向平齐站位，单条候选不得单独越站；多条U-turn再按短径到长径的逆序N沿轴向法线同步相向错开N×0.01m，短径平移更多、长径平移更少；同出口退出侧控制点保持簇侧向排序 |

#### 1.4.2 曲线形态规范

- **直行**：单段 Bezier，形态近平直，`arc/chord` ≈ 1，不能出现大转弯或 S 弯
- **左/右转**：单段 Bezier，单向弧状，`arc/chord` 长转弯 ≥ 1.08，短转弯 ≥ 1.03；禁止 S 弯
- **U 型调头**：显式三段式，首直+弧+尾直，先按同入/同出传递连通分量的 U 型轴向严格求得唯一弧段两端平齐站位；同分量多条U-turn按短径到长径的逆序N，让首端/尾端两个平齐点沿轴向法线同步以相同的 `N×0.01m` 距离相向错开，移动后仍保持轴向平齐和同出口控制点排序
- **优先单段表达**：在无物理避让、无固有形态影响的场景下，普通直行/左/右转必须使用单段 Bezier

#### 1.4.3 精细路口面生成

由道路边缘线、车道组端侧缩扩线围成可内凹的封闭多边形：
- mode=1/3：进入组向路口内回缩，退出组向路口外扩
- mode=2：进入组与退出组均向路口外扩

#### 1.4.4 性能需求

| 指标 | 要求 |
|------|------|
| 单路口生成时间 | 通常毫秒级，最差不超过 10 秒 |
| 典型复杂场景 | 53 条连通路口目标 2 秒内 |
| 多轮修复上限 | 最多 3 轮，每轮最多修复 12 条 |
| 非纯几何场景 | 小预算收口，最多 1 轮、最多 8 条重生成 |

## 3. 功能设计

### 3.1 顶层调度器（IntersectionShapeGenerator）

**职责**：输入规范化、拓扑校验、SDF 构建、子模块调度、异常处理、性能统计。

**接口**：
```cpp
class IntersectionShapeGenerator {
public:
    struct Config {
        double sdf_cell_size  = 0.2;   // SDF 网格分辨率（米）
        double obstacle_buffer = 1.0;  // mode=2 绕障清距（米）
        double kappa_max       = 0.25; // 最大允许曲率（1/m）
        LBFGSConfig lbfgs;
        ConnectivityDirectionConfig connectivity_direction;
    };

    bool generate(const IntersectionInput&, IntersectionOutput&);
    const ValidationReport& lastReport() const;
};
```

**拓扑校验规则**：
- 检查连通关系的声明转向类型与几何方位是否一致（角差 > 1 级时输出警告）
- 检查粗糙路口面是否自相交（自相交则返回错误）
- 检查 StopLine 的 associated_group_id 是否存在

**障碍物清距策略**：
```cpp
// mode=2 需保留 1m 绕障距离，其他 mode 只禁止穿行
double obstacleAvoidanceClearanceForMode(int mode) {
    return mode == 2 ? 1.0 : 0.0;
}
// mode=2 对 RoadEdge 非端点段也保留 1m 净距
double roadEdgeAvoidanceClearanceForMode(int mode) {
    return mode == 2 ? 1.0 : 0.0;
}
```

### 3.2 连通曲线生成器（ConnectivityGenerator）

**核心子模块**：

| 子模块 | 类 | 职责 |
|-------|----|------|
| 全局调度 | `GlobalCoordinator` | 按"直行→左右转→U型调头"和"由内到外"规划生成顺序 |
| 簇排序 | `ClusterOrderSolver` | 同簇空间排序、配对构造、结构性交叉检测 |
| 单曲线生成 | `generateOne()` | 初始曲线→优化→后处理→验证 |
| 拓扑修复 | `repair_pass` | 多轮修复残余同簇交叉 |
| 兄弟曲线 | `buildSiblings()` | 从已生成曲线中提取同簇邻居 |

**生成优先级**（`OptGroup::priority`）：
- 0: 直行（先生成，作为参考基准）
- 1: 左转、右转
- 2: U 型调头（最后生成，已有足够的兄弟曲线约束）

**同簇"由内到外"空间顺序**（`GlobalCoordinator`）：
- 进入簇：左调头→左转→直行→右转→右调头（CCW 方向）
- 先生成内侧（角度偏小）曲线，外侧曲线生成时内侧邻居已就绪

### 3.3 簇排序求解器（ClusterOrderSolver）

**排序规则**：

```
进入簇排序（主键降序，CCW在前=左侧在前）:
  主键: atan2(exit_pt - mean_entry)   角度差 > 2° 决定排序
  并列: 退出车道在退出组内横向位置（降序）
  最后: 进入车道在进入组内横向位置（降序）

退出簇排序:
  主键: entry_pt · exit_arm_left_normal（降序）
  并列: 退出车道在退出组内横向位置（降序）
```

**配对构造**：对排序后的 id 列表生成所有 `(i, j), i<j` 对，每对携带：
- `expected_side`：+1 = sorted[i] 在 sorted[j] 左侧
- `ref_perp`：mean_entry→mean_exit 的左法向
- `shared_endpoint`：共享同一进/退车道时为 true（仅标识合法首/尾连接点；连接点外仍禁止贴合、重叠或相交）

**结构性交叉豁免**（`CrossExemption::StructuralCross`）：

| 检测场景 | 判定条件 |
|---------|---------|
| 同进入组对侧退出 | `exit_lat_A × exit_lat_B < 0` 且 `|lat| > 3m` |
| 同进入组横向倒置 | `(entry_lat_A - entry_lat_B) × (exit_lat_A - exit_lat_B) < 0` |
| 进入簇 rank-lat 倒置 | `rank_diff × lat_diff > 0` |
| 退出簇 rank-lat 倒置 | `rank_diff × lat_diff > 0` |
| 左/右转 ↔ U型调头 | `a_uturn && turnB∈{L,R}` 或反之 |
| 对向交通流 | `entryDirA · entryDirB < -0.5` |

> **注意**：两个 U 型调头共享退出车道**不豁免**，可按"内层浅拱/外层深拱"有序排列。

### 3.4 惩罚代价函数（PenaltyCost）

联合代价函数包含 6 个惩罚项：

```
F(params) = w_smooth    × ∫κ²ds                           // 曲率平方积分（平滑项）
          + w_obstacle  × Σ max(0, clearance - sdf)²      // 障碍物穿透
          + w_boundary  × boundary_violation               // 边界穿越/越界
          + w_fence     × Σ outside_fence_dist             // 超出粗糙路口面
          + w_cluster   × cluster_violation                // 同簇非交约束
          + w_crosswalk × crosswalk_oblique_penalty        // 人行横道斜穿
```

**初始权重与自适应上限**：

| 惩罚项 | 初始权重 | 上限 | 自适应系数 |
|--------|---------|------|-----------|
| 平滑 | 1.0 | — | — |
| 避障 | 30.0 | 240.0 | ×1.8/轮 |
| 边界 | 10.0 | 160.0 | ×2.0/轮 |
| 围栏 | 6.0 | 96.0 | ×2.0/轮 |
| 同簇 | 20.0 | 96.0 | ×1.5/轮 |
| 人行横道 | 0.5 | — | — |

### 3.5 LBFGS 求解器（LBFGSSolver）

- 双循环递归计算逆 Hessian 近似，历史记录 m=10
- Strong Wolfe 线搜索（c1=1e-4, c2=0.9），最大 4 次线搜索
- 最大 12 次迭代，梯度收敛阈值 5e-4
- 支持冷启动 `solve()` 和热启动 `solveWarm()`
- 外层迭代 5 次（每次迭代后自适应调整惩罚权重）

### 3.6 符号距离场（SDFField）

- 将障碍物多边形栅格化为稠密网格（默认单元 0.2m）
- 查询返回 `(SDF值, 梯度向量)` 通过双线性插值
- 静态缓存：相同输入（roi+obstacles+cs+buf）复用，避免重复计算
- 支持多边形膨胀（ClipperLib）和并集运算

### 3.7 无解预检测（InfeasibilityDetector）

在生成每条曲线前执行快速预检，判定三类无解场景：

| 类型 | 检测方法 | 处理 |
|-----|---------|------|
| A: 通道过窄 | SDF 值 < `required_width` | 标记 WarnA2 |
| B: 围栏-障碍夹断 | BFS 在 SDF+fence 限定域内不可达 | 尝试放松围栏（最大扩展 1.5m） |
| C: 拓扑死锁 | BFS 可达性检测 | 生成 fallback 直线段，标记 Infeasible |

### 3.8 精细路口面构建器（IntersectionAreaBuilder）

**构建流程**：
1. 计算路口中心（车道端点几何中心）与参考半径
2. 优先尝试精细多边形构建 `buildFinePolygon()`
3. 回退到基于道路边缘截取法 `buildFromBoundaryElements()`
4. 按顺时针绕向组装多边形，顶点吸附容差 0.5m
5. 若多边形自相交，返回粗糙路口面作为降级输出

**缩扩端点计算**：
- 对每组的 lane/laneEdge（各自独立去重）端侧端点做垂线
- 垂线与所有连接线（进/退车道线 + 路口内连通曲线）的最近交点作为缩扩端点
- 同一 laneEdge 被进/退组共用时，只保留矢量化方向与当前组方向同向的缩扩点
- laneEdge 矢量化方向与当前组交通方向明显相反时，翻转进入尾端/退出首端语义，使用与组内车道连接点一致的路口侧端点

**道路边缘截取规则**：
- 缩扩线两端各延长 7.0m 与 RoadEdge 求交
- 同一 RoadEdge 多个交点时取距缩扩端点最近的那个
- 交点处 RoadEdge 局部方向需与当前组方向一致才有效（防止反向掉头边缘被打穿）
- 合并 RoadEdge 链保留原始段交通方向；只有一个有效交点时，根据原始方向与合并链方向是否反向选择路口侧，不能固定保留链首段或链尾段
- type=Other 但任一端与 RoadEdge 首尾相连的边缘作为桥接段参与合并

### 4.1 单曲线生成决策流（generateOne）

```

    │

    │   ├── bfsReachable? No → makeFallbackCurve → status=Infeasible
    │   ├── detectSandwich? Yes → tryRelaxFence → fence_expansion_applied
    │   └── narrow_passage? Yes → status=WarnA2（继续生成）

    │
    ├──► [U型调头分支]

    │    ▼ crosswalkClearanceBehind(p1, T1, crosswalks)  → min_lead1

    │                  + shape×5 + compact×0.5 + arclen×0.1
    │        硬过滤: 自相交/超出envelope/曲率超上限 → 拒绝
```

### 4.2 G1 端点强制（enforceG1）

优化结束后强制将首末控制点投影回切向射线：

```cpp
// 首段: ctrl[1] 投影到 p0 + λ × start_dir
lam = max((ctrl[1] - p0) · start_dir, 0.05);
ctrl[1] = p0 + lam * start_dir;

// 末段: ctrl[2] 投影到 p1 - μ × end_dir
mu = max((p1 - ctrl[2]) · end_dir, 0.05);
ctrl[2] = p1 - mu * end_dir;
```

λ/μ 下限 0.05 防止退化段（控制点与端点重合）。

对于无物理避让需求的普通单段曲线，`λ/μ` 同时受方向轴有效范围约束：默认不超过端点弦长；非直行、非U型调头的首/尾方向射线存在前向交点时，分别不超过端点到交点距离。控制点横向分量被投影为零。掉头和Obstacle/Boundary/Fence避让候选可跳过该单段轴向约束，转入专用分段或降级路径。

### 4.3 同簇约束惩罚（evalCluster）

三重检测机制：

**[A] 横向边距惩罚**（enforces expected_side）：
```
对每个采样点 i（仅跳过首尾连接点附近的数值噪声区）：
  diff_i = (curve_pt_i - sib_nearest_pt) · ref_perp
  若 expected_side=+1: violation = max(0, diff_i + 0.3)  // 本曲线应在左侧
  若 expected_side=-1: violation = max(0, -diff_i + 0.3) // 本曲线应在右侧
  cost += w_cluster × violation²
```

**[B] 符号变化惩罚**（防止曲线中部穿越）：
```
检测沿弧长方向 diff[] 的符号翻转
每次翻转: cost += w_cluster × 50 × depth
```

**[C] 穷举段相交检测**（捕捉弧分数交叉）：
```
for each (curve_seg_i, sib_seg_j):
    if segmentsIntersect AND 交点不在首尾连接点数值容差内:
        cost += w_cluster × 50 × depth
```

**ObstacleCross 弱化**：若相交点位于障碍物附近（SDF < 1.5m），标记 ObstacleCross，
将该配对的簇约束权重系数降至 0.4×（保持基本保序但不阻止避障）。

### 4.4 U 型调头形态设计（makeAlignedUTurnCubic）

单段三次 Bezier 编码"首直+中弧+尾直"模式：

```
ctrl[0] = p0
ctrl[1] = p0 + (lead0 + arc_handle) × T0 + lat_shift
ctrl[2] = p1 - (lead1 + arc_handle) × T1 + lat_shift
ctrl[3] = p1
```

**参数计算**：

1. **lead0/lead1**（首/尾直行延长距离，使拱弧顶点轴向平齐）：
   ```
   s0 = p0 · axis,  s1 = p1 · axis,  common_s = max(s0, s1)
   lead0 = max(0, (common_s - s0) / (T0 · axis))
   lead1 = max(0, (common_s - s1) / ((-T1) · axis))
   // 有 Crosswalk 时: lead0 ≥ crosswalkClearanceAhead
   // 无 Crosswalk 时: lead0 ≥ kUTurnNoCrosswalkMinLead (2.0m)
   // 先严格获得轴向平齐的q0/q1；同连接点同簇多条U-turn再按左到右顺序
   // 的逆序N取两侧最大值，将首/尾平齐点沿轴向法线同步相向错开相同的N×0.01m，
   // 避免首尾直行段重叠
   ```

2. **arc_handle**（半圆弧切向把手，基于经典 4/3·r 近似）：
   ```
   base_coef = 2/3    // r = turn_gap/2 → handle = (2/3) × turn_gap
   turn_gap > 4m 时平滑增长到 1.0
   arc_handle = max(0.5, coef × turn_gap × scale + handle_bias)
   min_lead > 1m 时: arc_handle = max(arc_handle, 0.3 × min_lead)
   ```

3. **lateral_bias**（横向扇开偏移，用于单段候选排序）：
   ```
   clamp 范围: [-tan(15°), +tan(15°)] × total_handle  (turn_gap < 4m)
               [-tan(30°), +tan(30°)] × total_handle  (turn_gap ≥ 4m)
   ```

### 4.5 人行横道跨越计算（crosswalkClearanceAhead）

```cpp
// 仅使用 Crosswalk 多边形，不使用 StopLine 代理
for each cw in input.crosswalks:
    score cw by its nearest edge station along the ray
pick the nearest cw toward the intersection center
return picked_cw_far + 0.30m
```

关键：先选从组端点朝路口中心遇到的最近 Crosswalk，再使用该面的 `far`
（远端投影）而非 `forward`（最近点投影）作为跨越距离。两侧都命中时只保留
这两个面的支持；单侧命中时保留全量支持，避免另一侧 lead 被压短。

### 4.6 RoadEdge 绕离修复（tryBoundarySafeCandidate）

当曲线有 Boundary 违规时，构造绕离 Boundary/RoadEdge 的单段或少量分段候选。显式首/尾 RoadEdge 贴合段不再合法，候选必须以完整曲线参与 Boundary、RoadEdge、同簇、形态和 fence 审计。
- 若 RoadEdge id 同时属于保留固有形态曲线，不把该 RoadEdge 用作贴边支撑

### 4.7 障碍物代价解析梯度（addObstacleGrad）

利用 SDF 梯度与 Bezier 基函数导数推导：

```cpp
for each sample point i at parameter t:
    d = sdf.queryWithGrad(c(t))       // (SDF值, 梯度)
    slack = d.first - obstacle_clearance
    if slack >= 0: continue           // 无违反
    coeff = 2.0 * w * slack           // 负值（穿透越深，梯度越大）

    // B_j(t) = Bezier基函数对控制点j的偏导
    B0 = (1-t)³,  B1 = 3(1-t)²t,  B2 = 3(1-t)t²,  B3 = t³
    grad[ctrl_j] += coeff * d.second * B_j(t)
```

### 4.8 弹性带平滑（elasticBandSmoothAdaptive）

后处理阶段用于降低残余高曲率：

```cpp
for iter = 1..max_iter:
    for i = 1..N-1 (内部点):
        k = localCurvature(pts[i-1], pts[i], pts[i+1])
        if k <= kappa_max: continue
        cen = circumcenter(pts[i-1], pts[i], pts[i+1])
        dir = (pts[i] - cen).normalized()   // 外接圆径向
        cand = pts[i] + dir × move_step     // 沿径向向外微移
        if sdf(cand) >= min_sdf AND polygonContains(fence, cand):
            pts[i] = cand
```

移动步长 0.03m，最大迭代 50 次，SDF 安全裕量 0.1m。

### 4.9 初始曲线构造（buildInitialCurve）

- **Level-0**（直线安全）：`makeCubicG1(p0, t0, p1, t1, alpha=0.33)`
- **Level-1**（穿障绕行）：
  1. 在 SDF 场中找最大间隙路径 `sdfMaxClearancePath()`
  2. 构造绕行 apex 点
  3. 分段或单段拟合绕行曲线
- 兄弟曲线采样点列传入用于选择绕行侧（避免与对向拱交叉）

### 4.10 多轮拓扑修复策略

```
repair_pass 1:  tryPureGeometryTopologyRepair
    for each crossing pair (cid_a, cid_b):
        候选集: alpha sweep + lateral offset + reversed tangent
        选择: 交叉数最少 AND 形态门槛（arc/chord, maxCurvature, 无自交）

纯几何场景: 最多3轮，每轮最多12条
```

## 5. 实现方案

### 5.1 Bezier 曲线数学实现

#### 5.1.1 曲线求值（BezierSegment::evaluate）

```cpp
// De Casteljau 算法 / 展开式
B(t) = (1-t)³·ctrl[0] + 3(1-t)²t·ctrl[1] + 3(1-t)t²·ctrl[2] + t³·ctrl[3]
```

#### 5.1.2 曲率（BezierSegment::curvature）

```cpp
// κ(t) = |B' × B''| / |B'|³
// B'(t)  = 一阶导数（切向量）
// B''(t) = 二阶导数
double k = cross2d(d1, d2) / pow(d1.norm(), 3.0);
```

#### 5.1.3 弧长数值积分（arcLength，辛普森法）

```cpp
// n=20 段辛普森积分
for i in 0..n-1:
    t0 = i/n, t1 = (i+1)/n, tm = (t0+t1)/2
    L += (|B'(t0)| + 4|B'(tm)| + |B'(t1)|) × (t1-t0) / 6
```

#### 5.1.4 G1 连续构造（makeCubicG1）

```cpp
// 标准 Hermite 端点切向 Bezier 段
// alpha 控制把手长度（默认 0.33）
double d = dist(p0, p1);
ctrl[0] = p0
ctrl[1] = p0 + alpha * d * t0.normalized()
ctrl[2] = p1 - alpha * d * t1.normalized()
ctrl[3] = p1
```

普通无避让、无固定形态曲线不会只使用统一 `alpha`。直行首选等弦中点
`M=(p0+p1)/2` 对应的统一把手长度 `h=chord_length/2`，但 `ctrl[1]`、`ctrl[2]` 仍分别沿首、尾切线轴生成，只有切线完全一致且与弦方向一致时才重合；普通左/右转在前向方向交点 `Q` 稳定时首选
`ctrl[1]=p0+2/3·(Q-p0)`、`ctrl[2]=p1+2/3·(Q-p1)`。该候选仍受弦长、
方向交点、曲率、单拱形态和同簇非交门禁约束；短急弯会补充非对称首尾
把手候选，避免较近一侧方向交点把另一侧把手一并压短。

#### 5.1.5 形态自适应采样（sampleByShape）

```cpp
// 结合直段等间距采样与弯曲段角度分辨率采样
// straightSpacing=3.0m, angularResolution=10°, minSpacing=0.05m
// 先按角度阈值细分，再按最小/最大间距修剪
```

### 5.2 SDF 场实现细节

#### 5.2.1 构建流程

```
1. ClipperLib::InflatePaths() 膨胀障碍物多边形（buf 距离）
2. ClipperLib::Union() 合并重叠的缓冲多边形
3. 在 BoundingBox roi 内建立 rows×cols 网格（cs=0.2m）
4. for each cell center pt:
       grid[r][c] = distToPolygons(pt, polys) × sign(insideAny ? -1 : 1)
```

#### 5.2.2 双线性插值查询

```cpp
// 将世界坐标映射到格网浮点索引
double rf = (pt.y() - roi.min_pt.y()) / cs_;
double cf = (pt.x() - roi.min_pt.x()) / cs_;
// 取四个邻格，按 dr/dc 权重双线性插值
double v = (1-dr)*(1-dc)*v00 + (1-dr)*dc*v01 + dr*(1-dc)*v10 + dr*dc*v11;
```

#### 5.2.3 梯度计算

```cpp
// 中心差分
gx = (rawAt(r, c+1) - rawAt(r, c-1)) / (2*cs_);
gy = (rawAt(r+1, c) - rawAt(r-1, c)) / (2*cs_);
```

#### 5.2.4 静态缓存

```cpp
// CacheKey = {roi, obstacles, cell_size, buffer}
static unordered_map<CacheKey, vector<double>, CacheKeyHash> cache_map_;

void build(...) {

    auto it = cache_map_.find(key);
```

### 5.3 LBFGS 求解器实现

#### 5.3.1 主循环

```cpp
SolveResult solve(CostFn fn, VecXd x0) {
    VecXd x = x0;
    VecXd g;
    double f = fn(x, g);

    deque<VecXd> s_list, y_list;  // 历史步长和梯度差

    for iter = 1..max_iter:
        if g.norm() < grad_tol: break  // 收敛

        // 双循环计算搜索方向 d = -H*g
        d = lbfgsTwoLoop(g, s_list, y_list);

        // Strong Wolfe 线搜索
        alpha = lineSearch(fn, x, d, f, g, xn, fn_val, gn);

        // 更新历史
        s = alpha * d;    y = gn - g;
        if s·y > 1e-10 * s.norm() * y.norm():
            s_list.push_back(s);  y_list.push_back(y);
            if s_list.size() > m: s_list.pop_front();
        x = xn;  f = fn_val;  g = gn;
}
```

#### 5.3.2 Strong Wolfe 线搜索

满足 Wolfe 条件：
- Armijo 充分下降：`f(x + α·d) ≤ f(x) + c1·α·g·d`（c1=1e-4）
- 曲率条件：`|g(x + α·d)·d| ≤ c2·|g(x)·d|`（c2=0.9）

### 5.4 四叉树空间索引（QuadTree）

```
- 根节点覆盖 BoundingBox roi
- 节点容量 capacity=8，超过则细分为 NW/NE/SW/SE 四个子节点
- 最大深度 depth_limit=8
- 插入: 曲线按包围盒插入对应叶节点
- 查询: queryRange 递归检查 bbox 相交的节点并返回曲线列表
- 用途: ConnectivityGenerator 中加速同簇兄弟曲线的空间检索
```

### 5.5 多边形布尔运算（ClipperLib）

使用 Clipper2/ClipperLib 实现：
- **膨胀（Inflate）**：障碍物/多边形缓冲，用于 SDF 构建和 RoadEdge 净距检查
- **并集（Union）**：合并重叠障碍物，避免重叠区域被双重计入
- **裁剪（Intersection/Difference）**：路口面多边形修剪

```cpp
    return {{"x", v.x()}, {"y", v.y()}, {"z", v.z()}};
}
Vec3d vec3dFromJson(const nlohmann::json& j) {
    double z = j.contains("z") ? j["z"].get<double>() : 0.0;
    return Vec3d(j["x"], j["y"], z);
}
```

完整支持类型：`Vec2d/3d、BoundingBox2d、LineString2d、Polygon2d、
Lane/LaneEdge/LaneGroup、Connectivity/Obstacle/Boundary/StopLine/Crosswalk、
IntersectionInput/Output`

#### 5.6.2 Shapefile 导出（iodata_shapefile.h）

### 5.7 高程插值实现

```cpp
// 沿弧长线性插值端点高程
double z0 = lane.geometry.points.back().z();   // 进入车道末点Z
double z1 = lane.geometry.points.front().z();  // 退出车道首点Z

double total = arcLength(xy_pts);
double acc = 0;
for (i in 0..N-1):
    t = total > EPS ? acc / total : i / (N-1);
    points[i].z() = z0 * (1-t) + z1 * t;
    acc += dist(pts[i-1], pts[i]);
```

### 5.8 Boundary 安全性判定（boundary_safety.h）

判断曲线采样段是否与边界线发生非端点接触、贴合、重叠或穿越：

```
RoadEdge/Boundary 接触规则：
  - 除曲线真实首尾连接点数值容差外，任意采样段与 Boundary/RoadEdge
    接触、贴合、重叠或相交均视为违规
  - 不再因方向平行、局部切触或首尾贴边段而豁免

中心侧越界（可靠 RoadEdge）：
  - 计算 signed_dist = cross2d(bnd_dir, pt - bnd_a) / bnd_len
  - center_signed > 0 时，signed_dist < -0.05m 表示越界到外侧
  - 回折 RoadEdge（center_signed 翻转）不使用此判据
```

### 5.9 车道边线生成器（EdgeLineGenerator）

> 当前在顶层调度器中已注释禁用，保留代码供后续启用。

**策略**：
1. 按 `(进入组, 退出组)` 对已生成中心线分组
2. 组内按进入车道 laneOrder 从内到外排序
3. 标记组内互相交叉的"特殊连通关系"
4. 相邻非特殊车道若进/退两侧都共享边界 → 生成一条共享中线（alpha=0.38 Bezier）
5. 最外侧右边、最内侧左边、特殊车道边线独立生成

**输出**：`ConnectivityLaneEdge`，`is_shared=true` 时被两条中心线共用。

## 7. 性能架构与优化

### 7.1 性能目标

| 场景 | 目标 |
|-----|------|
| 简单路口（< 10 条连通） | < 100ms |
| 典型路口（10-30 条连通） | < 1s |
| 复杂路口（53 条连通，`100000643.json`） | ≈ 1.4s（ISG_PROFILE 实测） |
| 最差情况 | < 10s |

### 7.2 关键性能策略

| 策略 | 实现位置 | 效果 |
|-----|---------|------|
| LBFGS 轻量配置 | `max_iter=12, max_line_iters=4` | 减少优化器调用次数约 60% |
| SDF 静态缓存 | `SDFField::cache_map_` | 相同路口重复调用零开销 |
| 四叉树空间索引 | `ConnectivityGenerator::quad_tree_` | O(log N) 兄弟曲线查询 |
| 对偶 SDF 分辨率 | `sdf`（0.2m）+ `sdf_coarse`（粗糙面） | 精细避障 + 快速预检 |
| 非纯几何小预算收口 | repair_pass 限制 1 轮 8 条 | 含障碍场景不退化为全量重生成 |
| U 型调头场景切换网格 | 障碍场景紧凑，纯几何宽网格 | 障碍场景快速收敛 |
| 曲线采样收敛 | 0.35m/160 点（兄弟默认 32 点） | 减少 evalCluster 约 35% |
| 哈希索引 CurvePair | `buildPairIndex()` 后 O(1) 查找 | 消除热循环中 O(pairs) 线性扫描 |

### 7.3 内存使用

| 结构 | 大小估算 |
|-----|---------|
| SDFField grid | `rows×cols×8 bytes`，200×200 网格约 320KB |
| BezierCurve（每条） | `segs × 4 × 2 × 8 bytes`，单段 64B |
| PenaltyCostCache | 每曲线约 `32 × 2 × 8 + sibling_polys×32×2×8` ≈ 几 KB |
| QuadTree | 与曲线数成线性，约 O(N log N) |

## 8. 异常处理与降级策略

| 异常场景 | 检测位置 | 处理策略 | 输出状态 |
|---------|---------|---------|---------|
| 拓扑校验失败 | `validateTopology()` | 返回 false，不生成任何曲线 | — |
| 通道过窄 | `preCheck::narrow_passage` | 继续生成，标记警告 | `WarnA2` |
| 围栏-障碍夹断 | `preCheck::detectSandwich` | 尝试放松围栏最大 1.5m，记录扩展量 | `WarnA2` 或 `Infeasible` |
| 拓扑死锁（BFS不可达） | `preCheck::bfsReachable` | 生成端点直连 fallback 线段 | `Infeasible` |
| LBFGS 发散/无改善 | `optimiseCurve` | 保留最优迭代解（非初始解） | `Degraded` |
| 同簇交叉无法消除 | `repair_pass 3` | 标注 `exempt_crosses` 列表 | `Degraded` |
| 障碍物强制交叉 | `checkAndMarkA2` | 弱化簇约束系数至 0.4×，允许必要交叉 | `WarnA2` |
| 路口面多边形自相交 | `IntersectionAreaBuilder` | 返回粗糙路口面作为降级 | `is_rough=true` |
| 未捕获异常 | `generate()` 最外层 catch | 清空所有输出，返回 false | — |

### 9.5 性能注意事项

新增任何涉及曲线生成、约束、排序、形态保护或验证的改动时，需要：

- 在 `datas/100000643.json` 上实测单路口生成时间，确认 `ISG_PROFILE=1` 下 < 10s
- 非纯几何场景（含 Obstacle/Boundary）与纯几何场景分别测试
- 新增约束项或修复逻辑需同步更新对应约束的回归测试（见 `test_intersection_input_regression.cpp`）
