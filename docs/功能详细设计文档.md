# 路口形态生成器 功能详细设计文档

> 版本: 1.1
> 适用范围: 自动驾驶高精地图路口几何形态生成
> 输入: 车道、车道组、连通关系、障碍物、边界、停止线、人行横道、粗糙路口面
> 输出: 连通曲线(中心线)、车道边线、精细路口面

---

## 1. 功能概述

本工程实现**路口几何形态自动生成**，从结构化路网数据派生：

1. **连通曲线** — 每条连通关系（进入车道 → 退出车道）对应的Bezier中心线
2. **车道边线** — 路口内部的车道左右边界线（支持相邻车道共享）
3. **精细路口面** — 由道路边缘、车道端点围成的可内凹封闭多边形

## 2. 输入数据模型

几何坐标点统一使用三维 `Vec3d{x,y,z}` 表达，高程 `z` 可由输入提供；历史二维 JSON 缺省 `z=0`。方向类字段（如 `normal_direction`、`crossing_direction`、车道端点切向）仍使用二维 `Vec2d`。现有约束、排序、避障、围栏和 Boundary 检查均按 XY 投影计算，高程只随坐标保留或插值，不参与平面拓扑判定。

| 数据类型 | 字段 | 说明 |
|---------|------|------|
| LaneGroup | id, role(Entry/Exit), lanes, boundaries | 同方向同侧车道组 |
| Lane | id, left_edge_id, right_edge_id, width, geometry, laneOrder | 车道，geometry末点(进入)/首点(退出)为路口端点 |
| LaneEdge | id, geometry, is_shared, shared_by | 车道边线 |
| Connectivity | id, entry_lane_id, exit_lane_id, turn_type, geometry(可选) | 连通关系，geometry为可选固有形态 |
| Obstacle | id, geometry, buffered_geometry | 多边形障碍物 |
| Boundary | id, type(RoadEdge/MedianStrip/GreenBelt/Other), geometry | 道路边界 |
| StopLine | id, geometry, associated_group_id, normal_direction | 停止线 |
| Crosswalk | id, geometry(Polygon2d), crossing_direction | 人行横道（面） |
| IntersectionArea | id, geometry, is_rough | 路口面（粗糙或精细） |

## 3. 输出数据模型

### 3.1 ConnectivityCurve（连通曲线）
```cpp
struct ConnectivityCurve {
    ConnId id;
    LaneId entry_lane_id, exit_lane_id;
    ConnTurnType turn_type;
    std::shared_ptr<BezierCurve> curve;  // 生成的Bezier曲线
    LineString2d geometry;               // 三维采样点列，Z按首尾端点高程沿弧长插值
    CurveStatus status;                  // OK/WarnA2/Degraded/Infeasible
    ViolationInfo violation;             // 违规信息
    LaneEdgeId left_edge_id, right_edge_id;
};
```

### 3.2 IntersectionArea（精细路口面）
封闭多边形，外环顺时针，可包含内凹，外环点为三维 `Vec3d` 坐标。平面拼面、排序、相交、绕向修复仍按 XY 投影计算；道路边缘截取点和端侧边界点保留或沿来源三维折线插值 Z，避免精细路口面生成后丢失输入高程。

## 4. 路口曲线生成 —— 核心流程与多重约束协同

曲线生成是本工程的核心，需同时满足**8 重约束**且彼此相互制约。下面按约束逐项展开实现方案及协同机制。

### 4.1 约束 1：端点G1连续约束

**含义**：普通直行/左转/右转曲线首点必须与进入车道末点切向G1连续，末点必须与退出车道首点切向G1连续；曲线自身不允许大拐角弯折；曲线自身不能自相交。U型调头首尾连接点为特殊场景：为分离同连接点多条掉头的首尾直行段，允许跳过端点G1检查。

**实现方案**：

| 环节 | 实现 |
|------|------|
| 初始曲线构造 | `makeCubicG1(p0, t0, p1, t1, alpha)` 直接生成端点切向一致的三次Bezier段；U型调头优先用显式"首直+中弧+尾直"分段候选表达，首尾连接点G1按业务特殊场景跳过 |
| 优化后处理 | `enforceG1(c, start_tan_dir, end_tan_dir)`：将首段ctrl[1]投影到 `p0 + λ·start_dir` 射线，末段ctrl[2]投影到 `p1 - μ·end_dir` 射线，λ/μ下限0.05避免退化段 |
| 自相交检测 | `curveSelfIntersectsBusiness(c, ep=1.0)`：对80点采样做O(N²)段对相交检测，跳过相邻段与首尾对接段，端点附近容差1.0m |

### 4.1.1 普通直行/左转/右转的基础形态表达

当一条非U型连通关系同时满足以下条件时，最终曲线必须使用单段三次Bezier表达：
- 无障碍物、Fence、Boundary/RoadEdge物理避让需求；
- 无输入固有形态需要保留；
- 非RoadEdge贴边修复场景。

基础表达规则：
- 直行：单段三次Bezier，形态近似平直，`arc/chord` 接近1，横向偏移和曲率受限；
- 左转/右转：单段三次Bezier，必须是单拱弧，不能出现曲率符号翻转或S弯；
- 普通单段曲线的 `ctrl[1]` 只能位于 `p0 + λ·T0`，`ctrl[2]` 只能位于 `p1 - μ·T1`。`λ/μ` 位于 `[0.05m, chord_length]`；两条方向射线的前向交点只作为无物理避让时的自然形态参考和候选排序基准，不再作为严格 Boundary 链避让的硬截断。控制点不得产生横向偏移，最终仍受弦长、单拱形态、曲率和自交门禁约束；
- 无避让、无固定形态的首选基础表达按几何类型确定控制点：直行先取等弦中点 `M=(p0+p1)/2`，以 `|M-p0|=|p1-M|=chord_length/2` 作为统一首尾把手长度，但控制点分别沿首、尾切线轴生成：`ctrl[1]=p0+h·T0`、`ctrl[2]=p1-h·T1`，其中 `h=chord_length/2`。因此首尾切线完全一致且与直行弦方向一致时两控制点重合；切线不一致时控制点保持等长但不强制重合，仍必须满足轴向和 G1 门禁。普通左/右转若首方向射线与尾方向反向射线存在稳定前向交点 `Q`，使用 `λ=2/3·|Q-p0|`、`μ=2/3·|Q-p1|`，等价于将以 `Q` 为中间控制点的二次 Bezier 精确升阶为三次 Bezier。交点反向、近似平行或任一交点距离超过 `1.5·chord_length` 时回退到有界弦长比例候选；短急弯若该首选候选违反弧长比或曲率上限，同样回退。
- 若单段候选会引入Boundary穿越、障碍/Fence风险，则该曲线进入避让路径，不再按“无避让单段”规则强制。普通同簇非重叠不相交不再作为多段Bezier豁免理由；同簇风险只参与单段候选排序，优先选择交叉更少的单段候选。
- 上一条对**所有**修复阶段成立，其中共享端点转向配对修复（`repairSharedEndpointTurnPairs`）过去是漏口：它的准入判据只看交叉计数（`cross >= cur_cross && shared >= cur_shared` 才否决），两段候选靠"共享端点交叉 7→5"单独进门，于是"段数并列时才比段数"的次级判据永远轮不到——多段候选恰恰是靠交叉数更低进来的。现在该阶段直接拒收多段候选，并整体跳过两段候选网格（`2×6×6×9×4×4 = 10368` 个候选）。判据是二者的性质不对称：`shape.ordinary.single_segment` 无豁免、且拆段带来的高曲率是永久的，而同簇相交是可计数、可豁免、且会被后续阶段重新洗牌的软指标。`100000385-u` 的 `16/38` 即为此故被拆成 `maxκ≈2.0`（局部半径 `0.48m`，弦长 `45m`）的两段形态；实测这笔交易还是**净亏**——换来的两个交叉在后续阶段重排邻居后就没了，最终配置下两段形态各自与 4 条同簇邻居相交（`13|16`、`14|16`、`15|16`、`17|16` 与 `35|38`…`39|38`），而首选单段形态一条不交。`ISG_LEGACY_SEGTIE=1` 恢复旧行为做 A/B。
- 非 U 型曲线的形态门禁除弧长比、曲率上限、曲率符号翻转之外，还检查**单向绕转跨度** `curveTurningSpan`（沿曲线累加有符号切向转角得到 running 曲线 `S(s)`，取 `max S − min S`），上限 `kMaxNonUTurnTurningSpan = 200°`。它补上了曲率符号翻转判据的盲区：后者每段只取有限个内部采样点并用死区过滤小抖动，绕圈过程中曲率始终同号时完全看不到（`100000385-u` 的 `14` 曾接受一条同向绕满一整圈、跨度 `448°`、首尾切向差只有 `88°`、局部半径 `0.5m` 的两段曲线）。不用"总转角 − 首尾切向夹角"的超量口径，是因为合法的 S 形换道弧总转角是两段弯之和、首尾切向却几乎不变，超量与真正的病态折返同量级（`110003285` 的换道弧 `14` 实测超量 `120.4°`），必然误伤；绕转跨度对 S 形只取较大的**单侧**弯角。实测 21 份数据集的最大合法跨度为 `179.6°`（`110003285` 的 `76`），门禁留有余量。`ISG_LEGACY_EXCESS=1` 可关闭该门禁做 A/B。
- 同簇共享首端或尾端的同向线束只能在首尾连接点数值容差内接触；不得共享前缀/后缀、贴合或重叠。U型调头的首尾导向直行段也必须相互分离，不能把相邻中弧交叉或lead重叠裁成合法结果。
- 同簇共享首端或尾端的直行-转弯、同向转弯以及左右转混合对，都进入严格共享端点 pair repair；修复候选必须使用端点方向轴上的单段控制点。方向交点优先用于排序和评分；当严格 Boundary/Fence 避让需要时，可以沿轴向延长把手，但不能横向偏移、形成自交或破坏单拱形态。
- 严格共享端点 pair repair 的候选判交容差对**共享端点对**取 `kSharedEndpointPairCrossTol = kMidSpanCrossEndpointTol = 1.5m`，与最终审计口径一致；非共享端点对仍用 `0.15m`。原因：同一连接点上的扇出成员在端点毫米级邻域内必然以 `±0.001~0.002m` 的横向间隙换侧（`|cos_tan| > 0.9996`，两条曲线在该处近乎相切），若沿用 `0.15m` 口径，凡是审计判定干净的候选都会被整批否决，配对因此"无解"（110003285 的 `80|81` 即为此故长期定格）。为了不把这类端点邻域互穿当成合法结果，同一候选在 `0.30m` 紧容差下仍与配对曲线互穿时计入**轻量评分惩罚**（权重 60），只在同等条件下偏向连接点邻域也干净的形态，候选唯一时不淘汰（110002479 的 `9|10`、`10|11` 由此收敛）。
- 严格共享端点 pair repair 的"这一对修不动"记忆必须把**两条曲线的实际控制点**一并计入 key。只按 `id + 配对类型` 记忆会用中间态几何永久屏蔽后续重试：110003285 的 81 曾与尚未修复的折角态 80 比对，全部候选被判穿越并写入记忆，随后 80 被修成最终形态时 81 已无法重试。
- 严格共享端点 pair repair 的候选枚举分两遍：第一遍用常规网格；仅当第一遍仍留有同簇交叉（`best_cross > 0`）时才进第二遍，追加**半步偏移网格**（相邻档位中点）与**等 κ0 等值线候选**（以配对曲线的共享端点转入率为参考，按 13 档比例 × 9 档首把手采样反解尾把手）。第二遍只接受**同簇交叉严格更少**的候选，避免仅因曲率/弧长评分更漂亮就改写第一遍已收敛的形态。
- 共享端点上的"近直行 × 近直行"对同样计入 pair repair 的同簇交叉账本（`sharedEndpointStraightPairParticipates`）。此前该类对被排除在账本外、却被最终审计统计，于是修复过程会把违约悄悄搬到这类对上（100000012-nu 的 16 为躲 88 度左转把 κ0 抬到 0.0590、越过 14 的 0.0554，凭空造出 `14|16` 与 `12|14`）。由于任何 `pair_phase` 都不以这类对为修复目标，搬到其上基本无法再挪走，因此单列计数并在评分中重罚（权重 400）；但**不做硬拒**——硬拒会让近直行成员全部无法让位，实测反而使 100000012-nu 的违约由 3 升到 4。
- 共享进入端点的普通左/右转按几何有符号转向拆成左侧组、右侧组，各组内外侧曲线的首把手不得短于内侧曲线，保序间隔为 `0.25m`；共享退出端点对尾把手执行对称规则。左右两侧不做统一把手排序，直行不纳入该单调规则；`左/右转-掉头` 的 StructuralCross 豁免对和所有几何掉头均跳过普通把手排序。把手排序只用于修复真实共享端点交叉，不能替代全曲线相交检测。
- 内/外侧判定使用自由端点到共享端点切向射线的垂距（`sharedEndpointFanOutwardness`）：垂距更大者转弯半径更大，属外侧。该度量在整族内一致且与配对枚举顺序无关；不得改用配对参考法线上的横向投影绝对值比较——共享端点对的两个投影恒为等大反号，比较结果会退化为浮点噪声，同一扇出族内可得出自相矛盾的内外结论。
- 把手排序链只包含自由端方向一致的成员（`sharedEndpointFanDirectionsAligned`，方向余弦 ≥0.90）。同一进入车道上指向其它出口 arm 的近直行等成员靠方向本身分离，不与真正的同 arm 扇出成员混入同一排序链，避免用无关成员的把手长度作为保序下限。
- 共享进入或共享退出的两条单段三次 Bezier，其控制多边形折线 `P0→P1→P2→P3` 之间不得出现"非重合、非控制点"的交叉（`sharedEndpointControlPolylinesCross`）。控制多边形是曲线的凸包骨架：共享端点且该端点切向相同时，任意一处互穿都意味着两族控制多边形不再嵌套，曲线必然在非端点处交叉。只比较两条中间连线 `P1→P2`（`sharedEndpointMidControlSegmentsCross`）是该规则的特例，无法覆盖"一条曲线的中间连线穿过另一条曲线首/尾把手连线"的情形（110003449 的 23|24 即为 24 的 `P1→P2` 穿过 23 的 `P2→P3`）。允许的接触只有两类：两段共线重合（同入侧首把手沿同一进入切向天然重叠），以及交点落在任一控制点的 `0.30m` 邻域内。该判定作为把手排序修复候选的显式剔除前兆，比采样相交判定更早更稳定；在严格共享端点 pair repair 中作为评分惩罚（不做硬剔除，否则候选集枯竭会把本该修好的真实相交留在原地）。
- 含几何 U 型调头的 StructuralCross 豁免对不进入严格共享端点 pair repair。U 型调头紧贴自身短弦，任何到达同一出口的普通转向都会紧邻其弧身；为"躲开"结构性允许的交叉而改写普通转向，会把把手推出正常范围（110003449 的左转 23 被推到 `h0=31.4/h1=40.0`、`arc/chord=1.24`），进而破坏真正必须保持的同入扇出嵌套 23|24。豁免对该保持权威，只有两条普通转向组成的同侧/异侧对才允许被该阶段改写。

实现收口：纯几何拓扑修复后执行基础表达恢复，先尝试自然单段、当前安全多段折叠成单段、非对称首尾把手单段候选；候选必须不增加固定形态交叉且无物理风险。同簇非重叠风险不再阻止普通直行/左转/右转恢复单段表达，只作为候选排序惩罚。最终标注前还会对无物理风险的非法普通单段执行轴向重建收口，只有在不增加同簇交叉和固定形态交叉时才替换。

共享端点把手调整后执行最终普通形态审计。若单段转弯因保序被压成曲率过高的短急弯，优先尝试方向交点升阶候选，再搜索首尾非对称把手和对称弦长比例候选；只有候选通过轴向控制、单拱形态、自相交、物理风险、固定形态交叉和同簇交叉门禁时才替换。方向交点越界本身不取代严格物理避让判定，避免 Boundary 链场景在“物理安全”和“自然参考形态”之间无解。

**关键代码**（`src/optimizer/penalty_cost.cpp::enforceG1`）：
```cpp
// 首段: ctrl[1] 投影到首点切向射线并限制有效范围
lam = clamp((c1 - p0)·sd, 0.05, start_handle_max);
c1 = p0 + lam * sd;
// 末段: ctrl[2] 投影到尾点切向射线并限制有效范围
mu  = clamp((p1 - c2)·ed, 0.05, end_handle_max);
c2  = p1 - mu * ed;
```

`start_handle_max/end_handle_max` 默认为端点弦长；普通左右转的前向方向交点存在时，优先候选使用端点至交点距离，但严格物理避让候选允许在弦长上限内沿轴向延长。`PenaltyCost::constrain_single_cubic_axes` 仅对无物理避让的普通单段曲线启用；掉头和已判定需Obstacle/Boundary/Fence避让的曲线转入专用候选/分段流程。所有最终普通单段仍必须满足轴向、弦长、单拱形态、曲率和自交门禁；`validate()` 与 `evaluateOrdinaryShape()` 使用同一口径，防止后续拟合绕开生成器门禁。

### 4.2 约束 2：同簇非端点不相交约束（核心）

**含义**：
- 同进入点（组）的线簇：除端点外不能有任何相交
- 同退出点（组）的线簇：除端点外不能有任何相交
- 该约束对线簇中**所有转向类型**生效（不仅限于调头）
- 例外：逻辑上存在交叉（拓扑倒置、不同arm或对向交通流交叉）的曲线对豁免；同向线束的转向组合中只有 `左/右转 ↔ U型调头` 允许穿越相交豁免。该豁免不覆盖贴合或重叠。直行-掉头、掉头-掉头、直行-直行、左转-左转等其它同向组合均不得存在非端点贴合、重叠或相交。
- 同簇曲线首端/尾端只允许真实连接点附近的数值容差接触；不得裁掉共享段后再检查剩余部分。
- 同入/同出同向线束获取组方向时，若组内存在直行连通，优先取进入/退出切向夹角最小的直行方向；没有直行时取组内最左侧进入/退出 lane 的方向。若具体进入/退出 `Lane::attrs["CON_NUM"] == "1"`，该 lane 保留自身端点切向，不被组方向改写。

#### 4.2.1 簇排序（`ClusterOrderSolver::build`）

**进入簇排序**（按"由内到外 = 左调头→左转→直行→右转→右调头"）：
```
主键:  DESCENDING atan2(exit_pt - mean_entry)
       角度差 > 2° 决定排序 (CCW在前 = 左侧在前)
并列:  DESCENDING 退出车道在退出组内横向位置 (稳定同向多车道)
最后:  DESCENDING 进入车道在进入组内横向位置
```

**退出簇排序**：
```
主键:  DESCENDING entry_pt · exit_arm_left_normal
并列:  DESCENDING 退出车道在退出组内横向位置
```

#### 4.2.2 配对构造（`addPairsFromSortedCluster`）

对每个簇内排序后的id列表生成全部 `(i, j), i<j` 配对：
- `expected_side = +1`：sorted[i] 应位于 sorted[j] 左侧
- `ref_perp`：配对特定横向参考轴（mean_entry→mean_exit的左法向）
- 共享退出车道或共享进入车道时 `shared_endpoint = true`：仅标识首/尾合法连接点，用于端点侧向排序和连接点容差判断；连接点外仍禁止贴合、重叠或相交。

#### 4.2.3 结构性交叉检测（`detectTopologicalInversions`）

| 检测场景 | 判定条件 | 处理 |
|---------|---------|------|
| 同进入组对侧退出 | `exit_lat_A × exit_lat_B < 0 且 |lat|>3m` | StructuralCross |
| 同进入组横向倒置 | `(entry_lat_A - entry_lat_B) × (exit_lat_A - exit_lat_B) < 0` | StructuralCross |
| 同进入组rank-lat倒置 | `rank_diff × lat_diff > 0` | StructuralCross |
| 同退出组rank-lat倒置 | `rank_diff × lat_diff > 0` | StructuralCross |
| 左/右转 vs U型 | `(a_uturn && turnB∈{L,R}) || (b_uturn && turnA∈{L,R})` | StructuralCross |
| 非共享端点对向交通流 | `entryDirA · entryDirB < -0.5`，例如 `100000643` 的 `78-97/99` | StructuralCross |
| **两个U型调头共享退出车道** | **不豁免** — 可按"左进=内层浅拱、右进=外层深拱"有序排列 | 受约束(shared_endpoint=true) |

#### 4.2.4 簇约束惩罚（`PenaltyCost::evalCluster`）

三重检测确保同簇非端点不相交：

**[A] 横向边距惩罚**：
```
对每个采样点 i (仅跳过首尾连接点附近约2%的数值噪声区):
  diff_i = (curve_pt_i - sib_pt_nearest) · ref_perp
  若 expected_side=+1: violation = max(0, diff_i + 0.3)
  若 expected_side=-1: violation = max(0, -diff_i + 0.3)
  cost += w × violation²
```

**[B] 符号变化惩罚**（保序）：
```
检测沿弧长方向相邻采样点的 diff[] 符号翻转
每次翻转: cost += w × 50 × depth
```

**[C] 穷举段相交检测**（跨弧分数交叉）：
```
对每对 (curve_seg_i, sib_seg_j):
  若 segmentsIntersect 且交点不在首尾连接点数值容差内:
    cost += w × 50 × depth
```

#### 4.2.5 共享端点处理

共享进入车道或共享退出车道的配对，仅首尾连接点本身允许相遇。实现上只排除连接点附近的数值噪声，连接点外的前缀/后缀贴合、重叠或相交均作为违规；`左/右转 ↔ U型调头` 只豁免几何穿越相交，不豁免贴合或重叠。

### 4.3 约束 3：穿障需避障约束

**含义**：曲线必须避开障碍物，不能穿行；当 `IntersectionInput::mode=2` 时还必须保留 1m 绕障距离，其他 mode 只要求不穿行。避障优先于其他约束（除同簇非交硬约束）。

**实现方案**：

| 环节 | 实现 |
|------|------|
| SDF构建 | `SDFField::build(roi, obstacles, cs=0.2, buf=obstacleAvoidanceClearanceForMode(mode))`：mode=2 使用 1m 缓冲，其他 mode 使用 0m 缓冲 |
| 障碍物代价 | `evalObstacle`: `Σ max(0, clearance - sdf)²`，权重30.0（最高） |
| 解析梯度 | `addObstacleGrad`: 利用SDF梯度 + Bezier基函数导数，O(N×S)开销 |
| 初始曲线绕行 | `buildInitialCurve`：若直线路径穿障，从SDF采样障碍物AABB，构造绕行apex |
| U型调头避障 | `solveUTurnMultiConstraint`：网格搜索时每个候选计算 `obst_pen`，权重200加入联合代价 |
| 障碍物豁免A2 | `checkAndMarkA2`：若实际相交点位于障碍物附近，标记ObstacleCross（弱化0.4×权重，非零） |

**关键代码**（`addObstacleGrad`）：
```cpp
slack = d - obstacle_clearance;
if (slack >= 0) continue;  // 无违反
coeff = 2.0 * w * slack;   // 负值
B1 = 3*(1-t)*(1-t)*t;     // ∂c/∂ctrl[1]
grad[base+0] += coeff * (gd[0] * B1);
```

### 4.4 约束 4：不能穿行/超出道路边缘约束

**含义**：曲线不能贴合、重叠或穿行任何不可通行 Boundary；除首尾连接点的数值容差外，曲线非端点与 Boundary/RoadEdge 的任何接触、重叠或相交都视为违规。当 `IntersectionInput::mode=2` 时，曲线非端点段还需与 RoadEdge 保持 1m 净距。普通 RoadEdge 仍按“道路边缘线与路口中心之间”的中心侧判外；仅当边段长度足够支持有限线段的侧向推断时启用该半平面，短连接片段（<2m）不外推为无限半平面，真实接触和净距仍独立检查。若整条 RoadEdge 贴近精细 `area.outer`（最大采样偏差≤0.60m），视为围栏轮廓的重复报告，同样不启用无限半平面。对于回折 RoadEdge 或局部中心侧符号翻转，逐段中心侧半平面不再可靠，改由完整 Boundary 接触/相交检测、曲线形态、fence 与最终审计共同约束。该约束属于物理避让约束，优先于同簇非端点不相交和固定形态保持。

**实现方案**：

| 环节 | 实现 |
|------|------|
| 公共判定 | `boundary_safety.h`: 构建 Boundary 段缓存；所有 Boundary 都禁止非端点接触、贴合、重叠和穿线；不再剥离首/尾贴合段，也不再将同向贴合或切触作为合法接触；RoadEdge 在中心侧可靠时额外检测外侧越界。Boundary 审计按 Bezier 段独立采样并保留拼接点 |
| 边界代价 | `evalBoundary`: 非 RoadEdge 非端点穿线硬惩罚 + 可靠 RoadEdge 外侧连续距离惩罚 + mode=2 RoadEdge 1m 清距惩罚，权重10.0 |
| 数值梯度 | `addNumericGrad`: 仅当代价非零时启用中心差分 |
| 候选过滤 | `assessCurveRisk`: Boundary 风险计入 `physical()`，候选搜索时优先剔除 |
| 最终修复 | `tryBoundarySafeCandidate`: 当前曲线仍有 Boundary 风险时，只保留绕离 Boundary 的保守单段/少量分段候选；显式首/尾贴合 Boundary 的三段式候选无效。候选需以完整曲线通过 Boundary、RoadEdge、同簇、形态和 fence 审计 |
| 几何容差 | Boundary/RoadEdge 接触检测仅排除曲线真实首尾连接点约0.15m邻域；Boundary polyline 首尾端点仍保留0.10m数值容差，内部折点按非端点处理；可靠RoadEdge中心侧越界容差0.05m |
| 出口审计 | `generateOne` 出口和 `generate()` 返回前均重新执行 Boundary 风险审计，防止形态/拓扑后处理重新引入穿越或越界 |
| 围栏约束（弱化版） | `evalFence`: 曲线点超出粗糙路口面时惩罚 `pointToPolygonDist × 2.0`，权重6.0 |

**端点共线擦碰豁免**（`endpointGrazeExemptSegmentMasks` / `curveBoundarySafetyIgnoringEndpointGraze`）：当一条 RoadEdge 折线的**端点**恰好落在连接曲线自己的端点上（位置容差 `0.60m`）、且从该端点走出的连续"共线走向段"与该端点车道切向基本同向（方向余弦 ≥ `0.70`）时，曲线**必须**从这里出发/到达，于是在这一小截共线段上以厘米级横向摆动跨过折线一到两次。这类接触是共享端点造成的数值擦碰，不是穿越；把它判成穿越会让曲线被误送进物理避让路径，从而跳过单段收敛与形态修复（`100000385-u` 的 `41/59/67/81/929910` 因此长期停在多段形态，实测擦碰深度只有 `0.004~0.107m`）。

豁免是**逐段、有方向**的：只对"贴合端点 → 共线走向段"这一段区间生效，且要求曲线相对该走向段的最大横向偏移（擦碰深度）不超过 `graze_tol = 0.25m`；发夹形路缘折回的另一条腿不在共线走向段内，因此仍在检查范围里，真正切进路缘照旧判违。中心侧可靠性仍按**整条**折线计算，被豁免的段不改变这一结论。`ISG_LEGACY_GRAZE=1` 可关闭豁免做 A/B。

### 4.5 约束 5：曲线形态不能超出粗略面约束

**含义**：曲线必须保持在粗糙路口面（fence）内。

**实现方案**：
- 围栏为输入数据的 `IntersectionArea.geometry`（粗糙面）
- 每个采样点用 `polygonContains(fence, pt)` 检查
- 越界点代价 = `pointToPolygonDist(pt, fence) × 2.0`
- 权重6.0，低于避障(30)和簇约束(20)
- U型调头网格搜索时硬过滤：`enforce_fence=true` 时拒绝越界候选

### 4.6 约束 6：人行横道附近调头需跨越约束

**含义**：调头进入组或退出组附近若存在人行横道（Crosswalk面），对应首/尾直行段必须完全跨越人行横道后，拱弧才允许开始/结束。

**实现方案**（`crosswalkClearanceAhead`）：

```cpp
// 1. 仅使用输入数据的 Crosswalk 多边形作为跨越源
//    不使用 stop_line 作为代理(与人行横道概念不同)
for (const auto& cw : input.crosswalks) {
    consider_polygon(cw.geometry);
}

// 2. 对每个 Crosswalk 汇总命中边段，按近端投影选择最近命中的那一块

// 3. 返回所选 Crosswalk 的 max_far + 0.30m 作为对应侧 min_lead
//    强制该侧直行段跨越人行横道后才进入/退出近半圆
```

**重要细节**：
- 用 `far`（线段远端投影）而非 `forward`（最近点投影），并先选择最近命中的 Crosswalk，避免更远的人行横道错误拉长
- 当单侧仅命中一块 Crosswalk 时，另一侧仍保留全量支持以免被压短
- `crosswalkClearanceAhead` 处理进入侧，`crosswalkClearanceBehind` 处理退出侧
- 单侧未找到Crosswalk时返回0，不对该侧施加2m；仅当进入/退出两侧都未找到Crosswalk时，首尾直行段才使用2m保底

### 4.7 约束 7：曲线输入固定形态不变约束

**含义**：若连通关系的 `geometry` 字段非空（坐标数>=2），除穿障必须避障时可重新生成外，其他场景不能修改固有形态。U型调头例外：最新调头形态约束优先于 fixed_shape，固定形态掉头也必须重新生成三段式。

**实现方案**：
- `hasFixedGeometry(conn)`: 检测 `conn.geometry.points.size() >= 2`
- `makeFixedGeometryCurve(conn)`: 将固有形态转为BezierCurve
- 生成流程入口先处理非U型固定形态曲线，加入 `preserved_fixed_ids` 集合
- 后续 `buildSiblings` 时，固定形态曲线作为兄弟传入但不再重新生成
- 仅当 `fixedGeometryHitsObstacle(conn, input, sdf)` 时重新生成
- 几何U型调头不进入 `preserved_fixed_ids`，统一走 `buildSegmentedAlignedUTurn` / `tryExplicitSegmentedUTurnIfSafe`，避免 fixed 折线破坏“直+弧+直”。

### 4.8 约束 8：调头形态满足首端直行段+单段掉头弧+尾端直行段

**含义**：U型调头曲线必须满足"首端直行段 + 单段掉头弧 + 尾端直行段"三段式表达；弧段两端点必须在U型轴向上平齐。该规则优先于固定形态和普通优化器输出，不允许最终以单段Bezier或任意多段S形表达调头。

首尾直行段长度规则：
- 进入组或退出组附近存在Crosswalk面时，对应首/尾直行段必须沿进入/退出方向完全跨越人行横道后，才允许进入中间掉头弧；
- 若只有一侧存在Crosswalk面，缺失侧不使用2m保底，只按弧段两端在U型轴向平齐的需要补长；
- 进入/退出两侧都无Crosswalk面时，首/尾直行段均需至少向路口内部拉伸2m后才允许开始/结束掉头弧；
- 多条U型调头先按配置家族的同入/同出传递连通分量严格求得唯一轴向平齐站位；`UTurnAlignmentScope::LaneEndpoint` 按 entry/exit 几何端点归并（同 lane_id 直接视为同端点），`UTurnAlignmentScope::LaneGroup` 按 `enterGroupId`/`exitGroupId` 归并。单条候选不得在该站位继续单独轴向前推。对于共享物理端点但入口/出口切向略有差异的成员，家族快照还必须汇总各成员达到共同站位所需的 lead 下限，不能把同一个标量站位分别投影到不同 U 轴后形成轴向台阶。随后按 `turn_gap`/端点距离短到长排序得到分量逆序N，沿轴向法线把首端/尾端两个平齐点相向错开，保持 q0/q1 的轴向站位一致，同时避免直行段完全重叠或贴合；错开量由家族统一裁定（见下"家族横向阶梯"）而非各成员独立取 `N×步长`；同出口中弧的退出侧控制点必须保持 `ClusterOrderSolver` 给出的侧向顺序；
- 若物理边界导致2m不可行，候选必须显式记录为避让/降级，不得悄悄回退成单段调头。

**实现方案**（`makeAlignedUTurnCubic` / 显式分段 U-turn 候选）：

基础候选仍可用单段三次Bezier编码"直+半圆+直"模式：
```
ctrl[0] = p0
ctrl[1] = p0 + (lead0 + arc_handle) × T0 + lat_shift
ctrl[2] = p1 - (lead1 + arc_handle) × T1 + lat_shift
ctrl[3] = p1
```

参数计算：
- **lead0/lead1**（进入/退出直线延长）：
  - `s0 = p0·axis`, `s1 = p1·axis`, `common_s = max(s0, s1)`
  - `lead0 = max(0, (common_s - s0) / T0·axis)`
  - `lead1 = max(0, (common_s - s1) / (-T1)·axis)`
  - 使拱弧顶点 q0=p0+lead0·T0 与 q1=p1+lead1·(-T1) 沿U型轴线对齐
  - 有Crosswalk面的一侧必须跨过对应人行横道后再进入/退出弧段；缺失侧仅随平齐补长；两侧均无Crosswalk面时首尾最短拉伸2m。

- **middle_arc**（中间单段掉头弧）：
  - 弧段端点 q0/q1 必须在U型轴向上平齐
  - 同配置家族多条U型调头按同入/同出传递连通分量严格求得统一轴向平齐的 q0/q1；家族范围可按实际车道端点或车道组切换，单条候选不得越过统一站位继续前推，再按 `turn_gap`/端点距离短到长排序得到逆序N，沿轴向法线将首端/尾端平齐点相向错开（错开量由家族横向阶梯裁定，见下），保持轴向平齐关系并打散首尾直行段重叠；同出口中弧退出侧控制点按簇排序保持侧向次序
  - 弧段长度与 q0/q1 间距之比需保持明显大于直线，避免压扁成贴近直线的短弯
  - 弧段沿U型轴向的鼓包需达到 q0/q1 间距的一定比例，使 `74-75`、`74-76` 这类近邻掉头按接近半圆的形态分离，而不是几乎贴在一起

- **arc_handle**（半圆弧切向把手）：
  - `base_coef = 2/3`（经典4/3·r 半圆Bezier近似最优值，r=turn_gap/2）
  - `turn_gap > 4m` 时平滑增长到1.0（更深拱弧）
  - `arc_handle = max(0.5, coef × turn_gap × scale + handle_bias)`
  - `min_lead0 > 1m` 时 `arc_handle = max(arc_handle, 0.3 × min_lead0)`

- **lateral_bias**（横向平移）：
  - 沿U型横向方向对称平移两个内部控制点
  - 用于单段候选的包络排序；显式三段式掉头的同连接点直行段分离由 q0/q1 相向靠近负责，端点G1按U型调头特殊规则跳过
  - 钳制范围: `tan(15°) × total_handle` (turn_gap < 4m) 或 `tan(30°) × total_handle` (turn_gap ≥ 4m)

生成器优先构造显式三段式 U 型调头：首段沿进入方向直行跨过人行横道或按无Crosswalk保底进入，中央段用近半圆单段弧形完成转向，尾段沿退出方向直行。该候选不再通过拆分已有单段曲线伪装分段，避免 `intersection_ds.json` 的 `20|22`、`intersection_jd.json` 的 `4|34` 这类纯几何调头退化成首尾不清晰的畸形弧；`100000012-nu.json` 的 fixed U型调头同样按此规则重生成。

- **家族横向阶梯**（`UTurnFamilyBuilder::familyLateralLadder` → `UTurnFamilyLadder`）：
  - 相向内缩量不能由每个成员各自算 `逆序名次 × 步长`。内缩受本成员走廊宽度限制（硬上限 `0.25 × radiusKey`，`radiusKey = |(exit_point − entry_point)·lateral|` 即该成员的 U 型走廊宽度），退化成员（走廊 0.3~0.4m）只能实现约 0.08m，而它外侧的邻居能实现完整的 `3×0.25 = 0.725m`，**阶梯反向**：外层成员的入口直段以约 4.7° 横切过内层成员的窄走廊。`100000412` 的 `34|36`（交点 d≈3.70m）、`16|18`（4.905m）、`8|10`（3.887m）即此成因。是否真的相交还取决于两条曲线谁先生成，因此逐条做的同簇审计抓不住它。
  - 因此改为**家族统一裁定**：
    1. 名义阶梯 `cap = min(step × 逆序名次, 0.25 × radiusKey)`，`step` 为家族统一步长（物理场景且家族规模 ≥ 3 时 0.25m，否则 0.01m）；
    2. **按入口侧、出口侧各自独立**裁定最终站位：按端点坐标重合（< 1e-3）把成员分成共享端点组，组内以最内层（半径最小）成员的自身走廊上限为预算 `budget`，取 `sep = min(step, budget / 组内成员数)`，沿半径升序做 `previous = min(cap[m], previous − sep)` 级联。级联**只在组内**进行，不跨组串联。
  - **两侧必须独立**是本机制的核心：家族是一条交替由"共享入口端点"和"共享出口端点"连接起来的链（例 `34—36` 共享入口、`36—35` 共享出口、`35—37` 共享入口），而内缩在入口侧沿 `+side×lateral`、在出口侧沿 `−side×lateral` 施加。用同一个标量同时表达两侧，等于要求半径次序在两条不同的链上同时单调：把某成员压小以让开它共享入口的退化邻居，就会让它相对共享出口的邻居反号。单标量口径实测在 `100000598`（3→6）、`100000699`（3→6）、`100000643`（5→6）、`100000643-0`（4→5）、`100000012-nu`（3→4）造出成对的 `N↔N−1` 反向违约。
  - **不采用"家族全体同量同向平移"**：字面实现该方案（由家族共享的直行/转向兄弟算出统一偏置量后整族平移）在 `100000412` 上需要 0.915m 的外移量，而进入车道没有这个空间，违约由 5 升到 20。家族层面裁定的阶梯达到同一目的（阶梯天然单调，越槽问题从根上消失）而不需要任何整体平移。
  - 阶梯对健康家族是**惰性**的：只要组内没有被走廊上限压掉的成员，`min(cap[m], previous − sep)` 就退化为原来的 `cap[m]`，输出不变。
  - **裁定与落实必须同一参考系**：阶梯在"车道端点"口径下裁定（`radiusKey`、上限 `0.25 × radiusKey`），`UTurnCurveInitializer::buildSegmented` 落实它时的走廊宽度 `lateral_gap` 与内缩方向 `side` 也必须按 `(p1 − p0)·lateral`（车道端点之间）取，**不能**按 `q1 − q0`（已经拉出直段之后的平齐点之间）取。入口切向与反向出口切向并非严格反平行，家族平齐站位强迫的长直段会在法线方向累积漂移，对退化成员足以让有符号间隙**翻号**：`110000703-u` 的掉头 `41` 实测 `T0·lateral = +0.017286`、两侧直段 9.3195m + 9.2385m、法线漂移 0.3208m，超过它自己 0.30991m 的整条走廊，间隙从 `+0.30991` 变成 `−0.01084`。三个后果同时发生——`side` 反号（分档朝外施加，小径被推到大径外侧）、走廊上限塌成 `0.25 × 0.01084 = 0.00271`（分档只实现 3.5%）、`*_stagger_orders_family` 因分档被压掉而为假（槽位钳制整体关闭，`+0.2309` 的出口偏置无阻施加）。同源之后 `buildSegmented` 的上限对家族上限**幂等**：家族已裁定过的分档不会被第二把不同口径的剪刀再剪一次。
  - **"分档是否完整落实"用容差判定**（`< 1e-6`）而非精确相等（`< 1e-9`）：两处上限同源后两者只差浮点末位，精确比较会因末位不同而静默关掉整个槽位钳制。
  - **退化为单段的成员拿不到任何档位**（已知局限）：`makeAlignedUTurnCubic` 在 `turn_gap < 1.5` 时硬置 `lateral_bias = 0`，且单段形态无法在不旋转端点切向的前提下承载横向偏移，因此这类成员只能实现第 0 档（`ctrl[1]` 精确落在切向中心线上）。这条局限在下面的"平齐站位走廊底限"引入后对 `110000703-u` 的 `41` 已不再触发（`41` 恢复三段式），但对其它因 Boundary/避障退化为单段的成员仍然成立。

- **平齐站位走廊底限**（`enforceStationCorridorFloor`，`UTurnCurveInitializer::buildSegmented`）：
  - 上一条规定"裁定与落实必须同一参考系"，即 `buildSegmented` 按车道端点口径 `(p1 − p0)·lateral` 取走廊宽度与内缩方向。这解决了**分档施加方向**反号，但没有解决**首尾直段本身**换侧：走廊口径改回车道端点后，`q0`/`q1` 在平齐站位处的有符号间距 `((q1 + q1_offset) − (q0 + q0_offset))·lateral × side` 仍然可能 ≤ 0。此时三段式的首直段与尾直段在离端点约 9m 处**真的交叉**，`curveSelfIntersectsBusiness` 会否决全部候选，掉头退化为单段，进而必然违反"人行横道附近调头需跨越"（单段没有直行段可言）。`110000703-u` 的 `41` 实测有符号走廊 `−0.01084`（叠加 0.0775 家族分档后 `−0.088`）。
  - 因此在落实分档之后、生成控制点之前，把**平齐站位口径**的有符号走廊抬到 `kMinStationCorridor = 0.30m`：外扩量只施加在**退出侧**（`q1_offset`），上限 `0.14 × lead1`（与 `g1_safe_inset` 同源），因为进入侧的站位还要承载人行横道净距与家族轴向平齐；`finalize_leads()` 之后重算，最多 4 次不动点迭代收敛。G1 余量用尽时保持修复前行为，不把缺口转嫁到进入侧。
  - **介入条件必须是"走廊已塌"（有符号走廊 ≤ 0）而不是"走廊偏窄"（< 0.30m）**。按 `< kMinStationCorridor` 介入会把走廊仍为正、只是窄的健康成员一并外扩，外扩改变了候选的曲率/圆度门禁结果，实测把 `intersection_cross` 的 `39`/`40` 与 `100000412` 一名家族成员从三段式**打回单段**。走廊为正时首尾直段不换侧，本就不存在自交死结，没有介入的理由。
  - `41` 修正后实测：`nseg=3`、`maxκ 107.198 → 7.298`、`lead0=9.3200`、`lead1=9.2388`、`q0.lat=+0.2386`、`q1.lat=+0.5386`、走廊 `+0.3000`，家族 `{45,43,44,41,13}` 的六个两两对全部 `curve_cross=false`。代价是 `41` 的出口横向站位从阶梯期望的 `−0.0775` 变成 `+0.3883`——这是有意的：走廊底限的优先级高于阶梯的名义档位，否则整条曲线拿不到三段式。
  - 调试开关 `ISG_STATION_CORRIDOR_FLOOR=0` 关闭该底限，用于源码级 A/B 消融。


- **平齐点横向偏置**（`entry_lateral_bias` / `exit_lateral_bias`，`UTurnCurveInitializer::buildSegmented`）：
  - 与上面的"相向内缩"不同，这是两侧独立的**有符号**偏置，沿U型轴法线把 `q0` / `q1` 各自推离轴线，用于把某一侧直行段整体推到共享出入车道上同簇直行/转向曲线的同一侧，从而消除"直段贴着车道中心线、在毫米级缝隙内换侧"造成的被迫非端点相交（`110003449` 的 `52|12`、`53|13`）
  - 偏置垂直于U型轴，**不改变 `q0`/`q1` 的轴向站位**，家族平齐与人行横道净距的物理依据不变；lead 由 `leadForChordWithLateralOffset()` 按偏置反解补偿，保证最小直行段的弦长读数不被偏置吃掉
  - 代价是首尾直段方向相对车道切向出现 `atan(bias/lead)` 偏差。形态约束 `shape.uturn.leads` 的门槛是方向点积 ≥ 0.98（约 11.5°），候选搜索按两级幅度供给：
    - **固定比例档位**：该侧 lead 下限的 5%（约 2.9°），分 0.50 / 1.00 两档递增，用于厘米级"贴着中心线换侧"这一类
    - **数据驱动档位**：按兄弟曲线在该侧直段跨度内的实测横向漂移反解所需偏置 `m ≥ max_d (L/d)·lat(d)`，取 1.15 倍余量后钳到硬上限 `0.14·lead`（约 8°，与 `buildSegmented` 的 `g1_safe_inset` 同源）。弯曲直行是长曲线，在掉头 12m 直段末端就能漂出 0.93m（约 4.45°），固定比例档位对这一类远远不够（`110003449` 的 `12|1`、`12|2`）
    - 数据驱动档位先尝试**双侧等量同向偏置**（整条中弧平移，弦长与两端切向关系不变，中弧曲率基本不动），被物理或同簇审计否决后才退回单侧偏置；单侧偏置会把该侧平齐点推向另一端、缩短中弧弦长并抬高曲率（掉头 1 实测 maxκ 0.59 → 0.96，弦长 4.01m 对应的业务上限为 6.0）
  - 只由 `SegmentedUTurnCandidateSearch` 的第二阶段在"存在共享端点的非掉头同簇兄弟"且主搜索仍带同簇交叉时启用；固定比例档位与数据驱动档位的单侧偏置只施加在兄弟贴合的那一侧，双侧平移为了保持中弧形态不受此门控约束（仍受各侧 G1 上限约束）。零偏置主搜索的候选顺序与优先级不受影响
  - **槽位钳制**：偏置不得把成员挤出自己的家族槽位。相邻名次的横向站位恰好相差一个 `step`，一旦某成员的偏置在**反**方向上超过半个 `step`，它就会越过上一名并与之相交（`110003285` 的掉头 52 曾被 +0.377m 反向偏置从 −0.995 推回 −0.620，越过 51 的 −0.746）。因此当该侧分档量**确实完整生效**（未被走廊上限或 G1 上限压掉，容差 `1e-6`）且 `step ≥ 0.10m` 时，把逆向偏置钳到 `0.4 × min(step, 本侧实际落实的分档)` 以内——分档只实现了一部分时槽位也按实现量收窄，否则钳制口径比它保护的次序间距还宽。钳制而非归零，是为了保留厘米级反向微调的分侧手段；`step < 0.10m`（纯几何输入的 1cm 分档）时家族次序不依赖横向站位，不钳制。调试开关 `ISG_NO_SLOT_CLAMP=1` 可关闭该钳制。

### 4.9 多重约束的协同机制

8重约束在以下场景中相互制约，需要综合处理：

#### 4.9.1 避障 vs 同簇非交

**冲突**：曲线为避障向一侧偏移可能挤压同簇兄弟曲线。

**解决**：
- 权重优先级：避障(30) > 簇约束(20) > 围栏(6)
- 避障违反时自适应放大权重至240，簇约束至多96
- `checkAndMarkA2`：若避障导致必须交叉，标记ObstacleCross弱化簇约束至0.4×（非零，保持基本保序）

#### 4.9.1.1 Boundary避让 vs 同簇/固定形态

**冲突**：同簇保序或固定形态可能把直行/左转曲线压到 RoadEdge 外侧；典型场景是 `100000012.json` 中直行 `2|7`、左转 `25` 与 `Boundary-43285966` 的交叉/越界。

**解决**：
- Boundary 风险作为 `physical()` 风险进入优化门禁，先于同簇形态评分处理。
- 对普通 RoadEdge 使用路口中心侧半平面：只允许曲线落在边缘线靠中心的一侧；对回折 RoadEdge 不使用不可靠半平面，但仍禁止非端点接触、贴合、重叠或穿行。
- 修复阶段按单条 Boundary 评分，避免“所有 Boundary 一起算”时被其它 RoadEdge 掩盖；直行端点开口场景可先降低已违规 Boundary 总分。
- 对回折 RoadEdge，可生成端点开口短段和保守绕离候选；不得沿 Boundary 形态贴合到切点，也不共享贴边切点。因这类边界中心侧符号会翻转，不使用逐段中心侧半平面误判自然绕行侧。
- 若固定形态或同簇约束与 Boundary 冲突，优先降低 Boundary 风险；同簇交叉通过后续拓扑修复继续收敛，并在返回前再次执行 Boundary 审计。

#### 4.9.2 同簇非交 vs 人行横道跨越

**冲突一**：同arm上多个U型调头获得不同人行横道跨越距离会导致拱弧顶点深度不一致，破坏有序排列。

**解决**：
- `crosswalkClearanceAhead` 使用 `far`（远端投影）而非 `forward`（最近点投影）
- 确保同arm上所有U型调头获得一致的跨越距离
- U型调头求解器在网格搜索中同时考虑 `lead0_extra` 与 `lateral_bias`，保持两条拱弧的横向有序

**冲突二（走廊翻转型死局）**：当掉头自身的端点走廊窄到与"人行横道逼出的首尾直段长度"不相容时，两条约束**在几何上无法同时满足**，必须显式定优先级。

判据（`segmentedUTurnCorridorInverts`）：端点走廊 `corridor = |(p1 − p0)·lateral| < 0.60m`，且首尾直段下限之和在法线方向的累积漂移 `(min_lead0 + min_lead1) × |T0·lateral| ≥ corridor`。满足即"真死局"；不满足只说明"当前没搜到更好的候选"，必须继续按严格规则修复。实测对照：

| 数据 | 走廊 | 直段下限 | 漂移 | 判定 |
| --- | --- | --- | --- | --- |
| `110000703-u` 的 `41` | 0.3099m | 9.318 + 9.237m（人行横道） | 0.3203m | **反转** |
| `100000643` 的 `125` | 0.1643m | 2m 保底（无横道） | 0.1136m | 不反转 |

**优先级：人行横道跨越 > 同簇非端点不相交**，且残余相交必须被约束在共享端点的**汇入收敛段**内：
- `SegmentedUTurnCandidateSearch` 由 `searchSegmentedUTurnTwoPass` 包成两阶段。第一阶段用严格同簇判定，与引入本机制前**逐字节一致**——任何当前能搜到合规候选的掉头，形态与耗时都不受影响。
- 第二阶段（结构性汇入豁免兜底）需**同时**满足三个前提：① 严格档在 832 个几何候选 + 偏置候选里一无所获；② 入参曲线确实违反人行横道分段要求（不是三段式、或中弧没能整体避开净空人行横道集合）；③ 走廊按上表判定反转。
- 第二阶段内部的配对级豁免（`sameClusterMergeFunnelTol`）还要求：恰好一条是掉头、该掉头端点走廊 < `kDegenerateUTurnCorridor = 0.60m`、且冲突落在共享端点的**收敛段**内。收敛段半径 `sharedEndpointMergeFunnelRadius` = 两条曲线自共享端点起保持 0.50m 内贴近的弧长（取两者较小值，上限 12m）。豁免只经 `curvesIntersectBusinessOutsideBalls` 生效，即**只挖掉共享端点那一个球**，另外两个端点的判定容差不被放宽；收敛段之外的任何穿越仍是硬违约。
- ②③ 是范围控制的关键，也是"每修一次掉头就触发一处旧违约"的机制所在：只按 ① 兜底，`100000643` 的 `125`、`115` 会一并被放行（它们的严格档同样返回 false，只是没能改进现状），`125-113`、`115-103` 由通过转为相交。附带收益是耗时——只有真正的死局才付两遍搜索的代价。
- 残余：`110000703-u` 的 `13|41`。`13` 是近直行、与 `41` 共享出口车道，其终点落在 `41` 的 0.31m 走廊内部，必须由走廊外进入走廊内，收敛段实测 9.869m。这是输入几何固有的拓扑，不是可修的造型缺陷。
- 调试开关：`ISG_MERGE_FUNNEL=0` 关闭豁免（同时跳过第二阶段，因为豁免关闭后两阶段判定等价），`ISG_DEBUG_MERGE_FALLBACK=1` 打印兜底档真正生效的位置。

#### 4.9.3 G1连续 vs 同簇非交

**冲突**：满足G1可能迫使曲线进入兄弟曲线区域。

**解决**：
- 非U型曲线G1由构造保证（makeCubicG1）；U型调头首尾连接点因平齐点分档内缩可跳过端点G1检查
- 优化后 enforceG1 强制投影回切向射线
- 簇约束通过控制点偏移或U型调头平齐点相向靠近实现，普通曲线仍与G1正交

#### 4.9.4 固定形态 vs 避障

**冲突**：固定形态曲线穿障时需重新生成，但约束要求保留形态。

**解决**：
- `fixedGeometryHitsObstacle` 检测固有形态是否穿障
- 仅穿障时允许重新生成，其他场景保留
- 重新生成时仍满足其他所有约束

#### 4.9.5 U型调头多约束求解

**冲突**：U型调头同时受端点G1豁免、避障、围栏、簇约束、人行横道跨越、最大曲率、拱弧形态多重约束；单段候选仍评估G1，显式三段式首尾连接点可跳过G1检查。

**解决**（`solveUTurnMultiConstraint`）：

网格搜索 `scale × lateral_bias × lead0_extra × lead1_extra × handle_bias`。障碍物场景使用紧凑候选网格，优先保证避障、围栏和人行横道约束的快速收敛；纯几何场景使用更宽的横向/深度网格，并开启近重叠检测，专门处理同入口/同出口 U 型调头的包络排序。
```
cost = 1000 × sib_x            // 同簇交叉数(高权重)
     + 200  × obst_pen         // 障碍物穿透
     + 200  × fence_ovf        // 围栏越界
     + 50   × (1 - g1_min)     // G1偏离
     + 20   × max(maxk-1, 0)   // 最大曲率
     + 5    × |arc/c - 1.55|   // 拱弧形态偏离
     + 0.5  × (|lat_bias|+|handle_bias|+0.3·lead0_extra)  // 紧凑度
     + 0.1  × |arc - ref_len|  // 弧长偏离
```

硬过滤：
- 自相交 → 拒绝
- 超出envelope → 拒绝
- maxk > 物理上限 → 拒绝

纯几何大 U 型调头优先尝试显式"首直+中弧+尾直"候选，并经过同簇非端点非交、Boundary、围栏和曲率门禁；端点G1按U型调头特殊场景跳过。只有候选不安全时才回退到网格搜索结果。若完整曲线集合生成后仍有残余 U 型调头拓扑冲突，则使用 U 型调头专用重生成；普通最终单段拓扑修复不接管 U 型调头。

#### 4.9.6 普通左/右转形态保护

非 U 型左/右转在避障和拓扑修复后必须保持单向弧状：
- 普通自然转弯优先保持明显弧长余量；共享端点同簇修复时若方向交点导致短急弯有效把手很短，可接受 `arc/chord` 约 `1.005~1.08` 的单向短弧，前提是控制点仍在首/尾方向轴有效范围内且能消除同簇非端点接触。
- 中长转弯仍要求可见单拱，不允许被障碍绕行或同簇修复压成近直线。
- 候选曲线需通过曲率符号检查，禁止由单向弧变成多 S 弯。
- 对障碍邻近左转优先尝试自然侧单段候选；只有同时满足避障、围栏、同簇非端点非交和形态阈值时才替换。
- RoadEdge 贴合候选已失效；形态和曲率符号使用完整候选曲线审计。

`100000643.json` 中左转 `118/119/120` 的回归指标：均保持单段 Bezier、无障碍/围栏侵入、无自交，`arc/chord` 约为 `1.105/1.116/1.131`，`maxCurvature < 0.20`。

#### 4.9.7 生成顺序保证

按"直行→左右转→U型调头"+"由内到外"的顺序生成，确保外侧曲线生成时内侧邻居已就绪，作为兄弟传入携带正确的 `expected_side`。

#### 4.9.8 多轮拓扑修复

纯几何场景允许多轮拓扑收口：
1. **第1轮**: 纯几何拓扑修复 (`tryPureGeometryTopologyRepair`) — 重试不同参数组合，选交叉最少的。
2. **U型调头专用重生成**: 对残余 U 型调头冲突使用完整兄弟集合重新进入 `generateOne`，保留调头包络语义。
3. **最终单段修复**: 只处理非 U 型曲线；对同入口 U 型调头与直行的近端冲突，增加沿 `ref_perp` 的入口前段轻量偏移候选，要求直行仍满足低曲率和 `arc/chord <= 1.08`。

非纯几何场景（含障碍物/Boundary）使用小预算收口：最多 1 轮、最多 8 条违规曲线重生成，关闭昂贵的全量 residual pass；初始生成已同时考虑物理风险、同簇和形态约束，避免单路口耗时退化到分钟级。

## 5. 精细路口面生成（IntersectionAreaBuilder）

精细路口面是封闭可内凹多边形，由道路边缘、车道端点、车道边线共同确定。构建过程统一使用三维 `Vec3d` 坐标承载路口面点，几何关系判断使用 XY，输出外环保留输入或插值得到的 Z。

### 5.1 输入

- 道路边缘线（`input.boundaries`，Type=RoadEdge）
- 进入/退出车道组端侧边界
- 已生成的连通曲线端点
- 已生成的车道边线（用于吸附）

### 5.2 构建流程

```
1. 计算路口中心与半径
   center = 车道端点的几何中心
   radius = max(端点到center的距离)

2. 优先尝试精细多边形构建 (buildFinePolygon)
   - 收集所有车道端点 + 道路边缘在路口侧的端点
   - 按角度排序围成多边形
   - 检测可内凹处(同arm多车道间的空隙) → 内凹处理
   - 若多边形顶点数>=4 → 直接返回

3. 回退到道路边缘裁剪法 (buildFromBoundaryElements)
   for 每条道路边缘 boundary[i]:
     a. 找到路口侧端点(距center更近的端点)
     b. 检查是否在路口范围内 (在粗糙路口面内 或 距center < 1.5×radius)
     c. 吸附到最近的车道边线端点 (snapTolerance=0.5m)
     d. 记录端点 → endpoints[i]

4. 端侧边界回缩/外扩
   for 每个车道组:
     - 进入组: 端侧边界向路口内回缩 groupCutOffset=0.5m
     - 退出组: 端侧边界向路口外扩 groupCutOffset=0.5m
     - lane、laneedge、boundary 是不同构面源类别，重复过滤只在各自类别内部进行
     - 同一 laneedge 被进入组和退出组共用时，仅保留 laneedge 矢量化方向与当前组方向同向的缩扩点，反向缩扩点忽略
     - laneedge 矢量化方向与当前组交通方向明显相反时，按组方向翻转进入尾端/退出首端语义，使用靠近组内车道连接点的路口侧端点生成缩扩点
     - mode=2 时进入组也按车道/边线几何方向向路口外扩；仅当端点切向与中心侧预期方向明显相反时才做中心校正，斜向道路保留原始几何方向
     - 边界折线两端外延 cutLineExtension=7.00m 对齐道路边缘

5. 与道路边缘相交时截取有效段
   - 仅计算两端延长后的端侧边界首尾端段与道路边缘的交点，组内中间段只用于连接端侧折线，不参与道路边缘截取
   - 交点按 XY 求解，截取道路边缘或端侧线时按对应三维折线里程插值 Z
   - 若进入组或退出组缩扩延长线与同一道路边缘有一个或多个交点，则取距离原始未延长缩扩线端点最近的交点作为该道路边缘截取点
   - type=Other 但任一端与 RoadEdge 首尾相连的边缘按 RoadEdge 桥接段参与合并，再由缩扩延长线统一截取有效段
   - 交点处 RoadEdge 局部方向需与当前组方向一致才写入道路边缘有效段 station，避免反向掉头边缘被打穿
   - 缩扩线自身裁剪保留原始端点语义，laneedge 端点不会被远处反向或非对应 RoadEdge 延长交点覆盖
   - 首尾探针由外延段和相邻的第一个原始端侧线段组成；若第一个原始段在距真实端点超过 1m 处命中当前组同源 LaneEdge/RoadEdge，该交点只是组端切线内部形点，只用于禁止切线被截短，不写入 RoadEdge station，避免同一几何以端侧线和道路边缘双重入环
   - 同一道路边缘只保留最外侧到最内侧命中的连续有效段，组内中间的内部边缘不再拆成独立拼面片段
   - 道路边缘合并时保留每个原始段的交通方向；单命中点若紧邻多个 RoadEdge 的共享端点，优先保留命中点到该共享节点的局部内凹弧，不能把共享节点另一侧的整条远端分支收入路口面；不满足局部节点条件时，才按合并链方向与命中组交通方向决定保留命中点前侧或后侧，方向元数据缺失时再回退到原始方向
   - 合并 RoadEdge 链首尾闭合时，两个缩扩命中点之间取凹向路口内的局部拓扑弧，而非远离路口内的外凸局部弧；两弧通过段中点相对“命中点弦线—路口中心侧”的带权有符号偏移比较，不以弧长长短作为业务依据
   - 保留中间 RoadEdge 的完整形态和两端相连 RoadEdge 的裁剪小段；同源或局部重合不是整链排除条件
   - 若只有进入组缩扩延长线截取，则取截取点到道路边缘终点
   - 若只有退出组缩扩延长线截取，则取道路边缘首点到截取点

6. 按顺时针绕向组装多边形 (winding="clockwise")
   - 沿路口外围依次连接有效段
   - 顶点吸附 snapTolerance=0.5m 合并近邻点
   - 用包含端点接触的简单环检查拒绝非相邻边相碰；若人工闭合边形成自接触环，按偶奇规则拆分并选取包含路口中心（否则面积最大）的外环，失败才进入回退

7. 返回 IntersectionArea { is_rough = false }
```

### 5.3 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| snapTolerance | 0.5m | 顶点吸附容差 |
| winding | "clockwise" | 多边形绕向 |
| groupCutOffset | 0.5m | 进入组内缩/退出组外扩距离 |
| cutLineExtension | 7.00m | 端侧边界两端外延长度 |

### 5.4 可内凹处理

当同arm存在多车道时，车道间的空隙形成路口面的内凹：
- 收集每条车道端点 + 车道边线在路口侧的端点
- 按角度排序后，相邻车道端点之间插入车道边线端点
- 形成可内凹的多边形外环

### 5.5 异常处理

- 道路边缘线不足 → 回退到凸包
- 端侧边界与道路边缘无交点 → 使用外延端点
- 多边形自相交 → 先用偶奇规则拆分自接触环并保留中心侧最大外环；拆分失败才标记错误并返回粗糙路口面

## 6. 关键算法

### 6.1 Bezier曲线表示

每条连通曲线由若干段三次Bezier段拼接：
```
B(t) = (1-t)³P0 + 3(1-t)²t P1 + 3(1-t)t² P2 + t³ P3
```

**G1连续**：相邻段在连接点切向一致。

### 6.2 LBFGS优化

拟牛顿法，存储最近m步历史：
```
for iter = 1..max_iter:
    g = grad(x)
    if ||g|| < grad_tol: 收敛
    d = -H·g  (双循环计算逆Hessian近似)
    alpha = lineSearch(d)  // Strong Wolfe
    x += alpha·d
```

### 6.3 弹性带平滑

迭代过程：
```
for iter = 1..max_iter:
    for i = 1..N-1:
        k = localCurvature(p[i-1], p[i], p[i+1])
        if k <= kappa_max: continue
        cen = circumcenter(p[i-1], p[i], p[i+1])
        dir = (p[i] - cen).normalized()
        cand = p[i] + dir × move_step
        if sdf(cand) >= min_sdf && polygonContains(fence, cand):
            p[i] = cand
```

## 8. 异常处理

| 异常 | 处理策略 |
|------|---------|
| 拓扑校验失败 | 返回false，输出错误列表，不生成 |
| 通道过窄 | 标记CurveStatus::WarnA2，仍生成最优曲线 |
| 围栏-障碍夹断 | 尝试放松围栏，仍失败则标记Infeasible |
| 拓扑死锁 | 生成fallback直线段，标记Infeasible |
| LBFGS发散 | 保留初始曲线，标记Degraded |
| 同簇交叉无法消除 | 标记Degraded并记录exempt_crosses |
